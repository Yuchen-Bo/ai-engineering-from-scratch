# NLP 技术与使用场景速查

> 覆盖 NLP 从基础文本表示到信息抽取、RAG 与 LLM 评测的算法、模型架构、解码策略、指标、数据集、框架和工程模式。每项先解释概念与工作方式，再给出简短使用场景。

## 使用说明

- **教学实现不等于生产首选。** “从零实现”用于理解机制；生产系统通常使用成熟库、预训练模型和经过领域验证的流水线。
- **模型名只是起点。** 上下文长度、许可证、语言覆盖、推理成本和模型卡会变化，落地前仍需在自己的数据上评测。
- **绝对化表述已修正。** 抽取式方法只能保证输出来自原文，不能保证结论正确；NLI、约束解码、RAG 和 LLM 评审都不能单独保证事实正确。
- **同名概念按语境区分。** FastText 的 subword 是字符 n-gram；BPE、WordPiece、Unigram 的 subword 是分词器产生的词元。

## 按任务快速选型

| 需求 | 优先起点 | 何时升级 |
|---|---|---|
| 小样本文本分类 | TF-IDF + 逻辑回归 | 语义、跨语言或长距离依赖明显时用预训练 Transformer |
| 低延迟关键词检索 | BM25 | 需要语义召回时加 dense retrieval，并用 RRF 融合 |
| 高质量 RAG 检索 | BM25 + dense + reranker | 关键词和语义都复杂时再加 SPLADE 或 ColBERT |
| 通用序列标注 | 预训练 Transformer + CRF/分类头 | 嵌套实体改用 span-based 或多遍抽取 |
| 受监管信息抽取 | 规则/抽取式模型 + 来源跨度 | 加 LLM 时必须保留 schema、provenance 和人工复核 |
| 文本生成 | 预训练 encoder-decoder 或 LLM | 需要格式保证时加 schema constrained decoding |
| 多语言分类 | XLM-R 类模型 | 用少量目标语言标注做 few-shot，并逐语言评测 |
| 长文问答 | RAG + 引用 + 拒答阈值 | 多跳问题加父子块、查询扩展或专用多跳检索 |
| 主题发现 | BERTopic（短文本）/ LDA（长文混合主题） | 语料很大时考虑 NMF、FASTopic 或分层聚类 |
| 对话任务 | schema + DST + 确认流 | 开放域再加 LLM、工具调用与混合路由 |

## 01 文本处理

**核心概念：** 文本处理是把人类书写的原始字符串转换成模型能够稳定消费的 token 和规范化表示。它不只是“清洗文本”，还决定哪些差异被保留、哪些差异被合并，例如大小写、词形、标点和 Unicode 变体。预处理规则属于模型契约的一部分，训练和推理必须完全一致。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 正则分词（Regex Tokenization） | 按预先定义的字符模式定位边界，把原始字符串切成词、数字、标点或业务字段；规则完全由开发者编写 | 教学、格式稳定的日志；缩写、URL、emoji 和自然语言边界复杂时不够稳健 |
| 词级分词（Word-level Tokenization） | 把完整单词视为最小 token，为每个不同单词分配词表 ID；词表外的新词通常只能映射为未知标记 | 经典 BoW、TF-IDF、Word2Vec；开放输入和多语言场景容易产生 OOV |
| 子词分词（Subword Tokenization） | 在完整单词和单个字符之间学习可复用片段，使高频词可以保持完整，罕见词可拆成多个已知 token | Transformer、开放词表、多语言模型；拆分效率取决于训练语料 |
| 字符/字节分词（Character/Byte Tokenization） | 字符方案把 Unicode 字符作为 token，字节方案把编码后的原始字节作为 token；字节方案能表示任意输入但序列更长 | 无空格语言、噪声文本和长尾字符；字符方案仍取决于字符覆盖范围 |
| Porter 词干提取（Porter Stemming） | 按多阶段英文后缀替换规则逐步削减词尾，把 `connected`、`connecting` 等词压到近似共同 stem；输出未必是真实单词 | 搜索索引、粗粒度归一化；结果不适合作为用户可见文本 |
| 词形还原（Lemmatization） | 结合词典、词性和语言形态规则，把屈折变化词恢复为词典基本形式，例如把 `ran` 还原为 `run` | QA、信息抽取和可解释特征；缺少正确词性时容易还原错误 |
| 词性辅助词形还原（POS-aware Lemmatization） | 先预测词性，再把 PTB 等标签映射成 WordNet 或形态分析器所需类别，使同形词按当前语法角色选择不同 lemma | 英文 NLTK 流水线；不能把所有词默认当名词处理 |
| 形态学（Morphology） | 研究词怎样通过词缀、屈折和构词发生形式变化，例如时态、数、格和派生；词形还原依赖这些语言规则 | 词形还原、形态丰富语言分析和子词设计 |
| NLTK 自然语言工具包 | 一个可分别调用分词、词性、词干、WordNet 和语言模型组件的 Python 工具包，组件之间需要显式接线 | 教学、实验和传统英文 NLP；大规模生产需评估速度与资源下载 |
| spaCy 工业级 NLP 流水线 | 将 tokenizer、词性、词形还原、依存分析和 NER 组件组合成一次文档处理流程，并提供统一 token/span 对象 | 生产预处理和信息抽取；模型与库版本必须固定并回归测试 |
| Transformer 配套分词器（Transformer Tokenizer） | 加载预训练 checkpoint 同时发布的词表、合并规则、特殊 token 和规范化配置，把文本转换为模型期望的 token ID | 微调和推理；替换词表会使 embedding ID 与训练参数错位 |
| 预处理回归测试（Preprocessing Regression Test） | 保存一组代表性输入及其期望 token、lemma 和规范化结果，在依赖升级后逐项比较是否发生非预期变化 | 防止库升级造成训练与推理分布漂移 |

## 02 BoW 与 TF-IDF

**核心概念：** 词袋模型（Bag of Words，BoW）把文档表示成词频向量，保留“出现了什么”，但丢弃“以什么顺序出现”。TF-IDF 在词频上进一步降低全语料常见词的权重，突出只在少数文档中频繁出现的区分性词语。两者产生的向量维度对应真实词项，因此速度快、容易解释，但无法直接表达同义词和长距离语义。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 词袋模型（Bag of Words，BoW） | 先建立全语料词表，再把每篇文档表示为各词出现次数组成的固定长度向量；`猫追狗` 与 `狗追猫` 会得到相同表示 | 分类、关键词分析和可解释基线；无法表达词序、同义词和上下文 |
| 词频向量器（CountVectorizer） | 将文本分词、词表学习、低频过滤和词频计数封装为一个转换器，输出文档-词项稀疏矩阵 | 快速建立经典文本分类与聚类基线 |
| 词频（Term Frequency，TF） | 衡量一个词在当前文档中出现多少次，可使用原始次数、除以文档长度的频率或对数缩放次数 | 表示词在单篇文档内的重要程度；重复堆叠同一词会抬高原始 TF |
| 文档频率/逆文档频率（Document Frequency / Inverse Document Frequency，DF / IDF） | DF 统计包含某词的文档数；IDF 对 DF 取反向对数，使几乎所有文档都有的词权重较低 | 搜索、分类和文档相似度；实际实现通常为零频和小语料加入平滑 |
| 词频-逆文档频率（Term Frequency-Inverse Document Frequency，TF-IDF） | 将文档内 TF 乘以跨文档稀有度 IDF，使“本文常见、全局少见”的词获得较大权重，结果仍是词表维度向量 | 小中型数据分类、关键词检索和审计解释；不理解同义表达 |
| TF-IDF 向量器（TfidfVectorizer） | 将分词、n-gram 词表、TF-IDF 计算和行归一化组合成一个可训练转换器，训练后可复用同一词表处理新文本 | 经典分类与检索基线；必须只在训练集上拟合以避免数据泄漏 |
| 词 n-gram（Word N-gram） | 把连续 n 个词拼成一个特征，例如 bigram `not good`；它保留局部顺序但不会理解更长句法关系 | 捕捉否定、固定术语和常见短语；n 增大时词表与内存迅速膨胀 |
| 最小/最大文档频率（`min_df` / `max_df`） | `min_df` 删除只在极少文档出现的词，`max_df` 删除几乎处处出现的词，从而控制词表规模与噪声 | 语料清洗和降维；需检查是否误删稀有业务词或类别关键词 |
| 对数词频（Sublinear TF） | 用 `1 + log(tf)` 替代原始词频，使一个词从 1 次增加到 2 次的收益大于从 100 次增加到 101 次 | 长文或词频分布偏斜的语料；避免重复词支配向量 |
| 停用词策略（Stopword Policy） | 根据任务决定是否删除高频功能词；删除会降低维度，也可能同时丢失否定、语气和句法信号 | 主题任务可尝试；情感分析、问答和短文本通常需要谨慎保留 |
| 稀疏向量/矩阵（Sparse Vector/Matrix） | 词表可能有数万维，但一篇文档只激活少数维度；稀疏结构只保存非零值及其索引，避免存储大量零 | 大词表文本表示和线性模型；无故转成 dense 会显著增加内存 |
| L2 归一化（L2 Normalization） | 用向量的欧氏范数除以每个分量，把文档向量缩放到长度为 1，使比较更关注词权重比例而非文档长短 | 让归一化向量的点积等价于余弦相似度 |
| 余弦相似度（Cosine Similarity） | 用两个向量点积除以各自范数，得到从 -1 到 1 的方向相似度；非负 TF-IDF 向量通常落在 0 到 1 | 文档相似度、检索和聚类；零向量需要单独处理 |
| TF-IDF 加权词向量（TF-IDF-weighted Embedding） | 先查出文档中每个词的静态 embedding，再以该词 TF-IDF 为权重做加权平均，兼顾词义向量与稀有词强调 | 轻量语义分类和文档表示；必须与简单 TF-IDF、平均词向量基线比较 |

## 03 Word2Vec 词向量

**核心概念：** Word2Vec 是从上下文共现中学习静态词向量的一组训练方法，而不是单个网络结构。训练完成后，每个词对应一个固定稠密向量；上下文相似的词通常在向量空间中更接近。它把离散词 ID 变成可比较的连续表示，但同一个词在不同语境中仍共用一个向量，因此不能解决一词多义。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 分布假设（Distributional Hypothesis） | 认为经常出现在相似上下文中的词往往具有相近含义，因此可以从“一个词周围通常出现什么词”间接学习语义 | Word2Vec、GloVe 等分布式表示方法的理论基础 |
| 独热编码（One-hot Encoding） | 用长度等于词表大小的向量表示一个词，只有该词 ID 对应位置为 1，其余位置全为 0 | 讲解 embedding 查表；维度高，任意两个不同词之间都没有语义距离差异 |
| 连续词袋模型（Continuous Bag of Words，CBOW） | 汇总中心位置周围的多个上下文词向量，并用它们预测被遮住的中心词；上下文内部顺序通常不被保留 | 大语料快速训练，常见词表示稳定；稀有词训练信号相对少 |
| 跳元模型（Skip-gram） | 输入一个中心词，分别预测窗口内可能出现的每个上下文词；一个中心词会产生多个训练词对 | 稀有词和领域词向量；训练样本更多，成本通常高于 CBOW |
| 负采样（Negative Sampling） | 把预测全词表的昂贵 softmax 改成若干二分类：真实共现词对为正例，从噪声分布抽出的词对为负例 | 大词表 Word2Vec 训练；负例数量和抽样分布会影响向量质量 |
| 嵌入表（Embedding Table） | 一个形状为“词表大小 × 向量维度”的参数矩阵；输入 token ID 相当于读取矩阵中的对应行 | 轻量向量查表和神经网络输入层；词表与行号必须固定 |
| 词嵌入（Word Embedding） | 用几十到几百维的稠密连续向量代替离散词 ID，使模型能够通过距离和方向表达从数据中学到的词语关系 | 相似词检索、文本模型输入和语义特征；关系只反映训练语料 |
| 静态嵌入（Static Embedding） | 每个词表项永久对应一个向量，不论它出现在什么句子中，`bank` 的金融和河岸含义共享同一表示 | 低算力、可解释特征和旧系统；无法处理一词多义和动态上下文 |
| 上下文化嵌入（Contextual Embedding） | 先让 Transformer 等编码器读取整句，再为每个 token 生成依赖左右上下文的向量，同一词每次出现可以不同 | BERT/Transformer 表示和序列标注；计算与存储成本高于静态查表 |
| 向量类比（Vector Analogy） | 用 `a - b + c` 的向量运算寻找最接近结果的词，检查空间是否编码性别、时态、国家首都等线性关系 | 诊断 embedding 结构；类比准确率高不代表下游任务一定好 |
| 最近邻搜索（Nearest Neighbors） | 计算目标词向量与词表其他向量的余弦相似度，返回分数最高的若干词及其距离 | 词表探索、领域术语检查和 embedding 调试；近邻可能反映偏见或共现而非同义 |
| 主成分分析/分布随机邻域嵌入（PCA / t-SNE） | PCA 用线性主方向压缩向量，t-SNE 用非线性概率邻域投影到二维或三维，便于观察局部词簇 | 可视化词簇和异常点；二维图受算法参数影响，不能当作原空间完整证据 |
| Gensim Word2Vec 实现 | Python 库 Gensim 提供 CBOW/Skip-gram、负采样、增量训练、向量保存和近邻查询实现 | 在自有领域语料训练或加载静态词向量 |
| Google News Word2Vec 向量 | 在 Google News 英文新闻语料上训练并公开的 300 维静态词向量，包含约数百万词和短语 | 旧系统兼容和英文基线；语料陈旧，语言、领域与社会偏见明显 |

## 04 GloVe、FastText 与子词表示

**核心概念：** GloVe、FastText 与子词分词代表三种解决“词如何变成向量或 token”的路线。GloVe 从全局词共现统计学习静态词向量；FastText 把词拆成字符片段后组合向量，从而近似表示未登录词；BPE 等子词算法则学习模型实际读取的词元词表。前两者主要回答“怎样表示一个词”，后者主要回答“怎样把文本切成模型词元”。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 共现矩阵（Co-occurrence Matrix） | 行列分别对应词，单元格记录两个词在指定上下文窗口内共同出现的次数；矩阵汇总的是全语料统计 | GloVe 和语料共现分析；词表大时矩阵极稀疏且占用空间 |
| 全局词向量（Global Vectors，GloVe） | 学习两个词向量的点积去逼近其全局共现次数的对数，并用权重函数降低超高频词对的支配作用 | 低成本静态英文表示；不能自然处理 OOV、一词多义和上下文变化 |
| 快速文本词向量（fastText） | 把一个词表示为完整词向量与多个字符 n-gram 向量之和；未见词也能由训练过的字符片段组合近似向量 | 拼写变体、复合词、形态丰富语言和 OOV 近似；形似词可能被误判为语义相近 |
| 字符 n-gram（Character N-gram） | 从单词内部滑动截取固定长度范围的连续字符片段，例如 3 到 6 个字符；每个片段可以拥有独立向量 | fastText 子词组合；与 tokenizer 输出的 subword token 不是同一概念 |
| 字节对编码（Byte-Pair Encoding，BPE） | 从字符或字节符号开始，反复把语料中最高频的相邻符号对合并成新 token，直到达到设定词表大小 | 从零训练语言模型 tokenizer；贪心频率合并不直接优化下游任务 |
| 字节级 BPE（Byte-level BPE） | 先把文本编码成 256 种原始字节，再在字节序列上学习 BPE 合并，因此任意字节串都能被表示 | 保证无未知字符的 tokenizer；非拉丁文本和 emoji 可能被拆成更多 token |
| 词片模型（WordPiece） | 从初始符号构造子词词表，并按训练准则选择能改善语料建模的片段；编码时将词拆为词表中的已知子词 | BERT 系模型；微调与推理必须使用 checkpoint 自带词表和规范化规则 |
| 句子片段工具（SentencePiece） | 直接在原始 Unicode 文本上训练 BPE 或 Unigram tokenizer，把空格也编码成普通符号，不依赖语言专用预分词 | 多语言、无空格语言和自建 tokenizer；它是工具，不是单一分词算法 |
| fastText 工具库（fastText Library） | 提供字符 n-gram 词向量的训练、预训练模型加载、词向量查询和文本分类接口 | 轻量多语言静态 embedding 与 CPU 部署 |
| Hugging Face 自动分词器（AutoTokenizer） | 根据 checkpoint 配置自动选择正确 tokenizer 类，并加载词表、合并规则、特殊 token 与预处理参数 | Transformer 推理和微调；用于避免手工选择导致词表错配 |

## 05 情感分析

**核心概念：** 情感分析是从文本中判断评价立场、情绪极性或针对具体对象的态度。最简单的任务把整段文本分成正面、负面或中性；更细的任务还要识别“评价的是谁或什么属性”。它本质上是带有强领域依赖的分类或结构化抽取问题，电影评论上的标签边界不能直接搬到客服、金融或医疗文本。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 极性分类（Polarity Classification） | 把整段文本映射为正面、负面、中性或有序星级等预定义标签；模型输出可以是类别，也可以是各类别概率 | 评论、客服和舆情；标签定义、讽刺和领域语气必须用真实数据校准 |
| 基于方面的情感分析（Aspect-based Sentiment Analysis） | 先识别被评价的实体或属性，再分别预测每个对象的情感；一句话可以同时包含多个相反极性 | “相机好但电池差”类细粒度产品反馈和客户体验分析 |
| 多项式朴素贝叶斯（Multinomial Naive Bayes） | 假设给定类别后各词计数条件独立，用类别先验与所有词条件概率的乘积比较不同类别；实践中在对数空间求和 | 极快的稀疏文本基线和小数据分类；独立性假设无法表达复杂词序 |
| 拉普拉斯平滑（Laplace Smoothing） | 给每个类别下每个词的计数加上常数，再重新归一化，避免测试文本出现未见词时整类概率变成零 | Naive Bayes 和计数模型；add-one 在大词表上可能过度平滑 |
| 逻辑回归（Logistic Regression） | 对特征做加权求和并经 sigmoid 或 softmax 转成类别概率，通过交叉熵学习每个词与 n-gram 的正负权重 | 可解释、稳定的生产分类基线；只能直接学习线性决策边界 |
| 线性支持向量机（Linear Support Vector Machine，Linear SVM） | 学习一个使不同类别间隔尽可能大的线性决策超平面，通常用 hinge loss 重点惩罚边界附近和分错样本 | 高维稀疏文本和类别边界清晰的分类；原始输出不是校准概率 |
| 否定范围处理（Negation Scoping） | 找出 `not`、`never` 等否定词影响的后续范围，并把范围内 token 改写为特殊特征，使 `good` 与 `not good` 可区分 | 经典情感模型；简单规则难处理双重否定、从句和隐式否定 |
| 二元词组特征（Bigram Features） | 把相邻两个词作为一个新的离散特征，例如 `not_good`，从而保留一小段局部词序 | 捕捉局部否定和固定搭配；增加词表稀疏度和内存 |
| L2 正则化（L2 Regularization） | 在训练损失中加入权重平方和惩罚，使模型倾向于使用多个较小权重，而不是依赖少数极大特征 | 防止高维稀疏分类器过拟合；正则强度需要交叉验证 |
| 精确率/召回率/F1（Precision / Recall / F1） | Precision 表示预测为某类的样本中有多少是真的，Recall 表示真实该类中找回多少，F1 是二者调和平均 | 类别不平衡时按类报告；必须说明正类和平均方式 |
| 宏平均 F1（Macro-F1） | 先独立计算每个类别的 F1，再不考虑类别样本量地等权平均，因此少数类失败会明显拉低总分 | 关注所有类别是否均衡；比 accuracy 更能暴露模型偏科 |
| 加权 F1（Weighted-F1） | 先计算每个类别 F1，再按真实样本占比加权平均；多数类对最终分数贡献更大 | 看总体样本表现；可能掩盖少数类完全失败 |
| 混淆矩阵（Confusion Matrix） | 行列分别表示真实类别和预测类别，单元格记录某类被预测成另一类的数量或比例 | 定位标签边界、相近类别和系统性误判 |
| ROC 曲线下面积/PR 曲线下面积（AUROC / AUPRC） | AUROC 衡量正例分数高于负例的整体排序概率；AUPRC 聚焦 precision-recall 折中，对稀少正例更敏感 | 极不平衡问题优先看 AUPRC；多类任务需说明 one-vs-rest 与平均方式 |
| Transformer 分类器（Transformer Classifier） | 用预训练 Transformer 读取完整文本，取特殊 token 或池化后的上下文表示，再接分类层预测情感标签 | 讽刺、长文、跨语言和方面情感；仍需领域标注和阈值校准 |
| scikit-learn 流水线（Scikit-learn Pipeline） | 按固定顺序把 TF-IDF 转换器和分类器封装成一个对象，训练、验证和预测都自动复用同一处理步骤 | 防止训练与推理预处理不一致，并支持整体交叉验证 |
| 斯坦福情感树库二分类子集（SST-2） | 从电影评论句子构成的英文正负情感数据集，标签是句子级二分类，常用于比较文本分类模型 | 英文情感基准；不能代表客服、金融、长评论或多语言生产分布 |

## 06 命名实体识别（NER）

**核心概念：** 命名实体识别（Named Entity Recognition，NER）从文本中找出连续或重叠的实体跨度，并给它们分配 PERSON、ORG、DATE、DRUG 等类型。任务同时包含“边界在哪里”和“属于什么类型”两个判断；只识别出部分名称通常仍算错误。NER 只负责发现和分类文本 mention，不负责判断两个同名 mention 是否是同一现实实体，那是实体链接的工作。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 实体词典/字典匹配（Gazetteer / Dictionary Matching） | 把文本片段与带实体类型的名称、别名或正规化词表进行匹配；命中后直接产生实体跨度与类型 | 稳定产品名、药名和法规名；召回率依赖词典覆盖与更新 |
| 规则式命名实体识别（Rule-based NER） | 综合大小写、词形、正则、上下文窗口和实体词典编写抽取规则，规则命中即可输出实体 | 小型固定领域、低延迟和高可解释场景；领域变化时维护成本高 |
| BIO 标注（BIO Tagging） | 为每个 token 标记实体开始 `B-X`、实体内部 `I-X` 或实体外部 `O`，其中 X 同时表示 PERSON、ORG 等实体类型 | 标准平坦实体序列标注；一个 token 只能有一个标签，不能直接表达重叠实体 |
| BILOU 标注（BILOU Tagging） | 在 BIO 基础上增加 `L-X` 表示多 token 实体末尾、`U-X` 表示单 token 实体，使边界状态更明确 | CRF 与序列标注；标签数更多，需要训练数据一致使用同一方案 |
| 隐马尔可夫 NER（Hidden Markov Model NER，HMM NER） | 用标签转移概率表示实体标签的相邻规律，用词在标签下的发射概率表示观测，再用 Viterbi 求最高概率标签序列 | 教学和轻量基线；难以利用丰富上下文与预训练表示 |
| 条件随机场（Conditional Random Field，CRF） | 同时计算各 token 的标签得分和相邻标签转移得分，对整条序列归一化并寻找总分最高的标签路径 | 少中量标注数据；要保证 BIO 合法仍需显式禁止非法转移 |
| 双向 LSTM-CRF（BiLSTM-CRF） | 双向 LSTM 为每个 token 编码左右上下文，线性层给出标签分数，CRF 再联合解码整条标签序列 | 传统高质量 NER 和受限部署；训练与推理无法像 CNN 一样完全并行 |
| Transformer 命名实体识别（Transformer NER） | 预训练 Transformer 为每个 token 生成上下文表示，再用 token 分类头或 span 分类头预测实体边界与类型 | 通用生产起点和领域微调；子词标签需要正确对齐回原文 |
| 跨度式 NER（Span-based NER） | 枚举或提议起止位置组成的候选文本跨度，再整体判断该跨度是否为某类实体，而不是给每个 token 单独分类 | 嵌套、重叠和长实体；候选跨度数量随文本长度增长 |
| 嵌套命名实体识别（Nested NER） | 允许一个实体跨度包含另一个不同类型实体，例如“Bank of America Tower”中组织名位于设施名内部 | 医学、法律和组织层级文本；普通 BIO 单标签序列无法直接表达 |
| 多遍命名实体识别（Multi-pass NER） | 按实体类型、层级或文档片段运行多次抽取，再合并各轮跨度，从而减少单次同时寻找过多类型造成的漏检 | 长文、稀疏类型和重叠实体；调用次数与合并复杂度更高 |
| LLM 零样本 NER（LLM Zero-shot NER） | 在提示中定义实体类型与输出 schema，不提供或只提供极少标注例子，让大语言模型直接返回实体文本与类型 | 新领域快速验证；输出必须校验原文跨度、类型和重复实体 |
| 分解式提示（Decomposed Prompting） | 把一次抽取拆成候选发现、含义解释、类型判断和复核等步骤，让每一步只解决一个较窄问题 | 生医和法律等难实体；成本更高，分步结果仍可能相互传播错误 |
| 基于检索的少样本提示（Retrieval-based Few-shot Prompting） | 为当前输入从已标注样本库检索最相似例子，动态放入提示后再执行 NER，而不是始终使用固定示例 | 小标注集的领域适配；必须隔离测试集，避免标签泄漏 |
| 实体级 F1（Entity-level F1） | 只有预测实体的起点、终点和类型都与标注完全一致才算正确，再据此计算 precision、recall 与 F1 | NER 主指标；token-level F1 会把部分边界命中计算成较高分 |
| seqeval 序列标注评测库 | 读取 BIO/BILOU 标签序列，将连续 token 还原成实体跨度，再计算实体级 precision、recall 和 F1 | NER 与其他序列标注评测；需要确认非法标签的处理方式 |
| spaCy 命名实体识别（spaCy NER） | spaCy 流水线中的实体组件，可使用统计模型或 Transformer 模型，并输出带字符跨度和类型的 `doc.ents` | 常规生产抽取和自定义训练；通用模型的标签集合未必符合领域需求 |
| Hugging Face NER 流水线（Hugging Face NER Pipeline） | 加载 token-classification checkpoint，完成 tokenizer、模型推理和相邻子词标签聚合，返回实体跨度及分数 | 快速试用预训练 BERT 类 NER；需检查子词合并与原文 offset |
| BioBERT / SciSpaCy 生物医学工具 | BioBERT 是生物医学语料预训练的 Transformer，SciSpaCy 提供科学与生物医学文本处理和实体模型 | 药物、疾病和科研文本；仍需按目标实体类型与领域语料验证 |

## 07 词性标注与句法分析

**核心概念：** 词性标注（POS tagging）判断每个 token 在当前句子中充当名词、动词、形容词等哪类语法角色；句法分析进一步描述词或短语之间如何组合。依存分析输出“哪个词依赖哪个中心词以及关系类型”，成分分析输出嵌套的名词短语、动词短语等结构。它们提供的是语言结构，不直接等于语义或事实关系。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 词性标注（Part-of-Speech Tagging，POS Tagging） | 根据 token 本身及上下文，为句中每个位置预测名词、动词、形容词等语法类别；同一单词在不同句子中可以有不同词性 | 词形还原、句法分析和规则抽取；标签只描述语法角色，不直接给出词义 |
| 宾州树库标签集（Penn Treebank Tagset） | 面向英文的细粒度词性体系，使用 `NN`、`NNS`、`VBD` 等标签区分名词单复数、动词时态和专有名词 | 英文传统流水线和兼容旧数据；不适合作为统一多语言标签集 |
| 通用依存句法规范（Universal Dependencies，UD） | 为多种语言定义统一的粗粒度词性、形态特征和依存关系，使不同语言的语法标注尽量可比较 | 多语言句法分析、跨语言迁移和语料标注；语言仍可有专属扩展 |
| 最常见词性基线（Most-frequent-tag Baseline） | 统计训练集中每个单词最常出现的标签，推理时无视句子上下文直接返回该标签，未见词使用全局默认标签 | 检查复杂模型是否真正有收益；歧义词与未登录词表现差 |
| 二元 HMM 标注器（Bigram HMM Tagger） | 假设当前词性只依赖前一个词性，并用当前标签下生成当前单词的概率建模，联合寻找整句标签序列 | 教学和轻量序列标注；独立与 Markov 假设限制上下文能力 |
| 维特比解码（Viterbi Decoding） | 用动态规划保存“到当前位置、以某标签结束”的最高累计分数及回溯指针，最后恢复全局最高分标签路径 | HMM 和线性链 CRF 的序列解码；比逐 token 贪心更考虑标签组合 |
| 成分句法分析（Constituency Parsing） | 把句子递归分解成名词短语 NP、动词短语 VP、介词短语 PP 等嵌套成分，最终形成以词为叶节点的树 | 语法教学、短语边界和层级结构分析；跨语言标注体系差异较大 |
| 依存句法分析（Dependency Parsing，Dependency Parse） | 为句中每个非根 token 选择一个中心词 head，并标注主语、宾语、修饰等依存关系，所有边共同形成一棵树 | 信息抽取、查询理解和修饰关系分析；解析关系不等于现实世界关系 |
| 基于转移的解析器（Transition-based Parser） | 从空栈和输入队列开始，模型逐步选择 shift、reduce、attach 等动作，直到构造完整依存树 | 低延迟增量解析；早期动作错误会影响后续结构 |
| 基于图的解析器（Graph-based Parser） | 为所有候选 head-dependent 边计算分数，再用最大生成树或其他全局算法选择满足树约束的边集合 | 需要全局一致性的依存解析；候选边评分和解码计算更重 |
| spaCy 句法解析器（spaCy Parser） | spaCy 流水线中的词性和依存组件，输入 `Doc` 后为每个 token 提供 `pos_`、`dep_` 和 `head` | 常规生产文本处理；模型支持的语言和标签质量需单独验证 |
| Stanza 多语言流水线 | Stanford NLP 提供的多语言 tokenizer、POS、形态、lemma 和 UD 依存解析工具，按语言加载独立模型 | 多语言研究和高质量句法分析；模型下载与推理成本高于简单规则 |
| Trankit 多语言流水线 | 基于 Transformer 的多语言 UD 工具，可在共享编码器上执行分词、词性、形态和依存分析 | 多语言 POS 与依存解析；部署前需检查目标语言模型与硬件成本 |
| NLTK 词性标注器（NLTK POS Tagger） | NLTK 提供的英文 `pos_tag` 接口，返回每个 token 的 Penn Treebank 标签，适合与 WordNet 词形还原组合 | 教学和小规模英文实验；不代表现代多语言最高质量 |

## 08 文本 CNN 与 RNN

**核心概念：** 文本 CNN 和 RNN 是 Transformer 普及前两类核心神经文本编码器。CNN 并行扫描局部 token 窗口，擅长发现与位置无关的短语模式；RNN 按顺序更新隐藏状态，显式保留前缀信息，适合流式输入。它们仍适用于小模型、低延迟和教学，但 CNN 对长距离关系不敏感，普通 RNN 则受串行计算和梯度传播限制。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 文本卷积神经网络（Text Convolutional Neural Network，TextCNN） | 将 token embedding 排成二维序列，用多个宽度的一维卷积核扫描连续片段，再把各通道最强信号拼成文档表示 | 短文本分类、边缘设备和快速基线；难以直接表示相距很远的词关系 |
| 可学习 n-gram 卷积核（Learnable N-gram Filters） | 每个卷积核覆盖连续 k 个 token embedding，并通过监督训练学会对某类局部短语模式产生高激活 | 情感、意图和主题分类；核宽决定可直接观察的局部范围 |
| 全局最大池化（Global Max Pooling） | 对每个卷积特征通道沿整段序列取最大值，只保留该模式在任意位置出现时的最强证据 | 位置不敏感的文本分类；会丢失模式出现次数、具体位置和顺序 |
| 普通循环神经网络（Vanilla Recurrent Neural Network，RNN） | 按顺序读取 token，把当前输入和上一时刻隐藏状态共同变换为新状态，并在所有时间步共享同一组参数 | 教学和短序列流式处理；长依赖受梯度消失与串行计算限制 |
| 随时间反向传播（Backpropagation Through Time，BPTT） | 将 RNN 按序列长度展开成共享参数的深网络，再从最后时间步向前累计梯度并更新循环参数 | 训练 RNN、LSTM 和 GRU；长序列会增加内存、计算和梯度不稳定性 |
| 梯度消失/爆炸（Vanishing/Exploding Gradients，Vanishing Gradient） | 梯度跨很多时间步反复乘以循环雅可比；乘积范数小于 1 时趋近零，大于 1 时快速放大 | 解释普通 RNN 长依赖失败；门控、梯度裁剪和归一化可缓解但不彻底消除 |
| 长短期记忆网络（Long Short-Term Memory，LSTM） | 在 RNN 上增加 cell state 与输入门、遗忘门、输出门，让网络学习哪些信息写入、保留和暴露 | 流式序列、低算力生成和传统序列标注；参数与计算多于 GRU |
| 门控循环单元（Gated Recurrent Unit，GRU） | 用更新门和重置门控制隐藏状态，在不单独维护 cell state 的情况下简化 LSTM 的信息保留机制 | 参数更少的序列模型；是否优于 LSTM 取决于数据和任务 |
| 双向循环神经网络（Bidirectional RNN） | 分别从左到右和从右到左读取同一序列，再拼接两个方向在每个位置的隐藏状态 | NER、POS 和离线分类；未来 token 不可见的严格流式任务不能使用反向分支 |
| 双向 LSTM-CRF（BiLSTM-CRF） | 用双向 LSTM 产生上下文化 token 表示和标签分数，再由 CRF 根据全句转移得分联合选择标签序列 | 中小数据 NER 和序列标注；推理含循环与结构化解码 |
| 冻结 Transformer 加小型任务头（Frozen Transformer + Small Head） | 固定预训练编码器参数，只训练其上方的线性层、CNN 或其他小型分类头，减少反向传播参数量 | 标注少和训练预算有限的任务；推理仍承担完整 Transformer 成本 |
| PyTorch `nn.Conv1d/LSTM/GRU` 组件 | PyTorch 提供的批处理卷积与门控循环层，封装可训练参数、前向计算、设备迁移和自动微分 | 实现 CNN/RNN 文本模型；需正确处理张量维度、padding 和序列长度 |

## 09 序列到序列（Sequence-to-Sequence）

**核心概念：** 序列到序列模型把一个可变长度输入序列映射为另一个可变长度输出序列。编码器先把输入转换成隐藏表示，解码器再根据该表示和已生成的 token 逐步预测下一个 token，直到结束标记。翻译、摘要和改写都符合这一结构；RNN 与 Transformer 的内部机制不同，但都可以采用 encoder-decoder 这一外部形式。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 编码器-解码器（Encoder-Decoder） | Encoder 把完整输入转换成隐藏表示，decoder 以该表示和已生成前缀为条件，逐 token 预测输出直到结束标记 | 翻译、摘要、改写和生成式 QA；encoder 与 decoder 可以由 RNN 或 Transformer 实现 |
| 固定上下文向量（Fixed Context Vector） | 早期 RNN seq2seq 只把 encoder 最后一个隐藏状态交给 decoder，相当于用固定维度向量概括任意长度输入 | 教学和短序列；输入变长时细节被压缩成严重信息瓶颈 |
| 序列交叉熵损失（Cross-entropy Sequence Loss） | 在每个目标位置取正确 token 的负对数概率，并对非 padding 位置求和或平均，作为整条输出序列的训练损失 | seq2seq 监督训练；它优化逐 token 似然，不直接优化最终文本质量 |
| 教师强制（Teacher Forcing） | 训练 decoder 第 t 步时输入真实的第 t-1 个目标 token，而不是模型刚预测的 token，使每步都在正确历史上学习 | 加速并稳定训练；造成训练时和推理时输入分布不一致 |
| 暴露偏差（Exposure Bias） | 训练时模型看到正确前缀，推理时只能看到自己的历史预测；一次错误会改变后续输入并可能连续放大 | 长生成容易漂移和重复；RNN 与 Transformer 自回归生成都存在此问题 |
| 贪心解码（Greedy Decoding） | 每个时间步直接选择当前概率最高的 token 并永久加入前缀，不保留其他候选路径 | 低延迟确定性输出；局部最优选择不保证整条序列概率最高 |
| 束搜索（Beam Search） | 每个解码步骤扩展当前候选，并只保留累计对数概率最高的 k 条部分序列，直到获得完整候选再排序 | 翻译和摘要等低多样性任务；beam 过大可能产生长度偏好与重复 |
| 温度采样（Temperature Sampling） | 用温度除以 logits 后重新 softmax 并随机采样；低温使高概率 token 更集中，高温提高低概率 token 机会 | 创意生成和多样候选；不适合要求唯一、可复现答案的任务 |
| 计划采样（Scheduled Sampling） | 训练初期主要使用真实前缀，随后按计划逐步用模型自身预测替换部分输入，让模型练习从错误历史恢复 | 缓解 exposure bias；训练目标存在统计一致性争议，收益需实测 |
| 最小风险训练（Minimum Risk Training） | 对模型生成的多个候选计算 BLEU、编辑距离等序列级损失，直接最小化这些损失在候选分布下的期望 | 让训练目标接近最终任务指标；候选采样和不可微指标使训练更复杂 |
| 强化学习微调（Reinforcement Learning Fine-tuning，RL Fine-tuning） | 把完整生成序列视为动作轨迹，由奖励模型或任务函数给分，再用策略梯度类方法调整生成概率 | 偏好和任务成功率等不可微目标；奖励设计与训练稳定性是主要风险 |
| RNN 序列到序列（RNN Seq2Seq） | Encoder 与 decoder 都由 LSTM 或 GRU 构成，encoder 状态初始化或持续条件化 decoder 的自回归生成 | 流式、边缘和教学；新通用任务通常优先预训练 Transformer |
| BART / T5 编码器-解码器模型 | BART 采用去噪重建预训练，T5 把任务统一成 text-to-text 格式；两者都能输入文本并自回归生成文本 | 摘要、改写和文本到文本任务；需选择与领域和长度匹配的 checkpoint |
| mBART / NLLB 多语言模型 | mBART 用多语言去噪预训练学习生成表示，NLLB 针对大规模多语机器翻译训练，二者都采用多语言 encoder-decoder | 多语言生成和机器翻译；支持语言、语言代码与 tokenizer 必须匹配 |

## 10 注意力机制（Attention）

**核心概念：** 注意力机制让模型在处理当前位置时，动态选择输入序列中哪些位置最相关，而不是把全部信息压进一个固定向量。模型用 query 与每个 key 计算相关分数，经 softmax 得到权重，再对对应 value 做加权求和，生成当前所需的上下文表示。Self-attention 在同一序列内部建立联系，cross-attention 则让一个序列读取另一个序列；注意力权重是计算中间量，不应直接当作模型推理原因。

**直观例子：** 在翻译句子时，decoder 准备生成某个目标词，它当前的隐藏状态形成 query；源句每个位置提供 key 和 value。与 query 最匹配的位置获得更高权重，因此这一步生成所用的上下文会重点汇总相关源词，同时仍保留其他位置的少量信息。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 注意力机制（Attention） | 对当前 query 与所有 key 计算相关分数，将分数归一化后对对应 value 加权求和，得到针对当前位置动态组织的上下文向量 | 序列对齐、上下文选择和 Transformer；计算成本随序列长度增长 |
| 查询/键/值（Query, Key, Value，Q/K/V） | Query 表示当前要寻找的信息，Key 表示每个位置可供匹配的索引特征，Value 表示匹配后真正被读取并汇总的内容 | 自注意力与交叉注意力的统一接口；三者通常由输入经过不同线性投影得到 |
| Softmax 注意力权重（Softmax Attention Weights） | 对所有位置分数取指数并除以总和，使权重非负且和为 1，然后把它们用作各 Value 的加权系数 | 计算上下文向量；高权重表示本次计算贡献较大，不等同因果解释 |
| Bahdanau 加性注意力（Bahdanau Additive Attention） | 分别投影 decoder query 与 encoder key，相加后经过 `tanh`，再用可学习向量压成一个标量对齐分数 | RNN 翻译和维度不同的 query/key 对齐；每个位置需要运行小型前馈网络 |
| 乘性注意力（Multiplicative Attention，Luong Dot Attention） | 用当前 decoder 状态与每个 encoder 状态直接做点积作为对齐分数；点积要求两种状态的维度相同 | 追求计算简单的 seq2seq；向量维度大时通常需要缩放以稳定 softmax |
| Luong 通用注意力（Luong General Attention） | 先用可学习矩阵投影 encoder 状态，再与 decoder 状态做点积，使原本维度不同的两组状态可以比较 | query/key 维度不同时使用；投影矩阵增加少量参数 |
| Luong 拼接注意力（Luong Concat Attention） | 拼接 decoder 与 encoder 状态，用带非线性的前馈网络把每一对状态映射为单个相关分数 | 经典注意力研究；计算形式接近加性注意力，实践中较少单独采用 |
| 对齐矩阵（Alignment Matrix） | 将每个输出位置对全部输入位置的注意力权重按行堆叠成二维矩阵；行表示输出步，列表示输入位置 | 翻译对齐可视化和错误分析；矩阵只能描述注意力计算，不能单独证明推理路径 |
| 自注意力（Self-Attention） | Q、K、V 都由同一序列投影得到，使每个 token 能按相关性读取序列中其他 token 的信息并更新自身表示 | Transformer 编码和全局 token 交互；需要 mask 时必须屏蔽 padding 或未来位置 |
| 交叉注意力（Cross-Attention） | Q 来自当前处理序列，K/V 来自另一组 encoder 或外部表示，使 decoder 能按需读取源序列或其他模态 | 翻译、摘要和多模态条件生成；源表示错误会直接影响输出 |
| 多头注意力（Multi-head Attention） | 将 Q/K/V 投影到多个较小子空间并行计算注意力，拼接各 head 输出后再做线性投影，使模型可学习多种匹配模式 | Transformer；head 数更多不必然更好，单 head 维度过小会限制表达 |
| PyTorch 多头注意力模块（`MultiheadAttention`） | 封装 Q/K/V 投影、缩放点积注意力、多头拼接和输出投影，并支持 attention mask 与 padding mask | 原型、教学和自定义模型；需核对 batch、sequence、embedding 维度顺序 |
| 注意力消融/反事实检查（Attention Ablation/Counterfactual） | 删除、置换或限制注意力连接，或扰动对应输入 token，再观察模型输出是否按预期变化 | 检查注意力热图是否与模型行为相关；单次可视化不能作为因果解释 |

## 11 机器翻译

**核心概念：** 机器翻译（Machine Translation，MT）把源语言文本转换为目标语言文本，同时尽量保持含义、语气、实体、数字和领域术语。现代神经机器翻译通常用 Transformer encoder-decoder：encoder 理解源文，decoder 通过 cross-attention 自回归生成译文。质量不只取决于模型，还受语对覆盖、tokenizer、术语约束、解码策略和评测方式影响。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 神经机器翻译（Neural Machine Translation，NMT） | 用神经 encoder-decoder 直接学习源语言序列到目标语言序列的条件概率，并通过自回归 decoder 逐 token 生成译文 | 通用翻译；低资源语言、领域术语和长句仍需专门数据与评测 |
| 平行语料（Parallel Corpus） | 由语义对应的源语言句子和目标语言译文成对组成，训练时模型以源句为输入、人工译文为监督目标 | 监督式 MT 训练和领域微调；错位、机翻回译和版权会影响数据质量 |
| 共享多语言分词器（Shared Multilingual Tokenizer） | 在混合语言语料上训练共同子词词表和 token ID，使不同语言共享输入 embedding 表并复用部分词片段 | 参数共享和跨语言迁移；零样本能力还取决于语料、目标与语言标记 |
| 交叉注意力解码（Cross-attention Decoding） | 目标语言 decoder 的每个生成步用当前状态作为 query，读取源语言 encoder 的 key/value 表示后预测下一个译文 token | Transformer MT 核心机制；源句 mask、语言代码和位置必须正确 |
| 束搜索（Beam Search） | 在每个目标 token 位置保留若干累计对数概率最高的候选译文，避免贪心解码过早锁定单一路径 | 确定性翻译；需配合长度惩罚、重复控制和终止条件 |
| 长度惩罚（Length Penalty） | 在比较 beam 候选时按输出长度重新缩放累计分数，抵消对短句或长句的系统性偏好 | 防止译文过短或异常冗长；系数必须在目标语言验证集调节 |
| 词汇约束解码（Lexically Constrained Decoding） | 在搜索过程中记录指定词或短语是否出现，只保留最终满足“必须包含”或“禁止出现”约束的候选 | 品牌、法律和医学术语一致性；强制词形不当会破坏目标语言语法 |
| 双语评估替补指标（Bilingual Evaluation Understudy，BLEU） | 计算候选译文与一个或多个参考译文的 n-gram precision，并用 brevity penalty 惩罚过短输出 | 语料级 MT 系统对比；句级波动大，同义改写会被低估 |
| 字符 F 分数（Character F-score，chrF） | 在字符 n-gram 层面计算 precision 与 recall，再按参数加权成 F-score，不要求词级切分完全一致 | 形态丰富语言和拼写变化明显的翻译；仍依赖参考译文 |
| COMET 学习式翻译评估 | 用预训练跨语言模型联合编码源句、候选译文和可选参考译文，再预测与人工质量判断对齐的分数 | 比较语义忠实度；具体 checkpoint、语言覆盖和是否使用参考必须固定 |
| BLEURT 学习式文本评估 | 在预训练语言模型上用合成扰动和人工评分微调，输入候选与参考后预测连续质量分数 | 参考式语义质量评估；领域外、语言外和版本变化需要重新校准 |
| SacreBLEU 可复现 BLEU 实现 | 固定参考文件处理、tokenization 和参数，并输出包含版本与配置的 metric signature，减少不同脚本算分差异 | 跨实验报告 MT 分数；必须保存完整 signature 而不只保存数值 |
| 无参考质量估计（Quality Estimation，QE） | 在没有人工参考译文时，根据源句和候选译文预测质量、错误标签或需要人工复核的概率 | 线上筛查和人工复核路由；模型分数不能替代专业译者评审 |
| 人工翻译评估（Human Evaluation） | 由合格评审者按含义保留、流畅度、术语、语体和错误严重度检查译文，并使用盲测与一致性控制 | 上线前高风险内容和自动指标校准；成本高且需清晰 rubric |
| 翻译幻觉（Hallucination） | 译文加入源文没有的事实、实体或修饰，或删除、替换关键含义；即使语言流畅也属于严重忠实度错误 | 医疗、法律和新闻 MT 风险监控；需源文对齐、实体数字检查和人工复核 |
| 不遗漏任何语言（No Language Left Behind，NLLB） | 面向大量语言对训练的多语言 Transformer 翻译模型族，通过语言代码指定源语言与目标语言 | 大规模多语言和低资源语对；通用语言覆盖不代表专业领域准确 |
| 多语言 BART（Multilingual BART，mBART） | 在多语言语料上用去噪重建预训练的 encoder-decoder，可在平行语料上继续微调为翻译或生成模型 | 多语言生成和 MT 微调；需要匹配语言代码与 SentencePiece 词表 |
| Marian / Helsinki-NLP 翻译模型 | Marian 是高效神经 MT 框架，Helsinki-NLP 发布了大量按固定语对训练的轻量预训练模型 | 固定语言对和低延迟部署；不同语对的模型质量与许可证需逐个检查 |
| ONNX 量化（ONNX Quantization） | 将模型导出为 ONNX 计算图，并把部分浮点权重与运算转换为 int8 等低精度格式，降低内存与 CPU 成本 | 浏览器和 CPU 推理；需复测算子兼容、速度与翻译质量 |
| LLM 翻译提示（LLM Translation Prompting） | 在提示中指定源/目标语言、风格、术语表和上下文，让通用大语言模型直接生成译文，无需专用 MT 接口 | 长上下文、风格和少样本术语适配；成本、延迟与可复现性较差 |
| 语言识别检查（Language-ID Check） | 对生成译文运行独立语言识别器，确认主要输出语言与目标语言代码一致，并记录置信度和混合语言比例 | 发现输出到错误语言的 off-target generation；短文本判断不稳定 |
| langdetect / fastText 语言识别（Language Identification，LID） | 根据字符或词片段分布预测文本所属语言及可选置信度，是两类常见轻量语言识别实现 | MT 输出语言检查；短文本、代码混合和相近语言要单独校准 |

## 12 文本摘要

**核心概念：** 文本摘要把一段或多段长文本压缩成较短内容，并尽量保留主要信息。抽取式摘要从原文选择句子，生成性风险较低但可能不连贯；抽象式摘要重新组织和生成语言，更流畅却可能引入原文不支持的事实。评测必须把信息覆盖、可读性和事实一致性分开看，单一 ROUGE 分数不足以决定能否上线。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 抽取式摘要（Extractive Summarization） | 对原文句子或片段评分并直接选取高分内容组成摘要，不改写内部措辞，因此输出词句都能在原文找到 | 合规和低生成风险摘要；仍可能断章取义、重复或保留不清晰指代 |
| 句子相似度图（Sentence Similarity Graph） | 把每个句子作为图节点，以词重叠、TF-IDF 或 embedding 相似度作为边权，连接内容相近的句子 | TextRank、LexRank 等图排序摘要；相似度定义决定图结构 |
| 文本排序算法（TextRank） | 在句子相似度图上迭代运行 PageRank，使与许多重要句子相连的句子获得更高中心性分数 | 无监督抽取式摘要和低算力基线；偏向重复中心信息而非新颖信息 |
| 词汇排序算法（LexRank） | 用 TF-IDF 余弦相似度构造句子图，再通过特征向量中心性或 PageRank 选取最具代表性的句子 | 多文档和新闻抽取摘要；阈值与文档重复度影响结果 |
| 潜在语义分析摘要（Latent Semantic Analysis Summarization，LSA Summarization） | 对词-句矩阵做奇异值分解，得到潜在主题方向，再选择能覆盖主要方向的代表句子 | 无监督抽取基线；主题维度、分词与词频预处理敏感 |
| 抽象式摘要（Abstractive Summarization） | 先编码原文含义，再由生成模型用新措辞压缩和重组信息，可以融合多句但也可能生成原文没有的内容 | 更自然、更紧凑的摘要；必须做事实性、实体和数字检查 |
| 双向自回归 Transformer（Bidirectional and Auto-Regressive Transformer，BART） | 使用 encoder-decoder 对被打乱、遮盖或删除片段的文本做去噪重建预训练，再在文档-摘要对上微调 | 新闻和通用英文摘要；输入超过上下文窗口会被截断 |
| 文本到文本迁移 Transformer（Text-to-Text Transfer Transformer，T5） | 把分类、翻译和摘要统一为“输入文本，生成目标文本”，采用 encoder-decoder 和任务前缀训练 | 多种摘要和改写任务；具体 checkpoint 的预训练与长度限制不同 |
| Pegasus 摘要模型 | 预训练时从文档中移除重要句子并让 decoder 重建这些句子，使训练目标接近摘要生成 | 新闻、科学和医学摘要起点；仍会产生事实错误 |
| 映射-归约摘要（Map-Reduce Summarization） | 先独立摘要每个文档块，再把所有局部摘要作为新输入生成全局摘要；第二阶段只能看到已压缩的信息 | 超过模型上下文的长文；局部遗漏会永久丢失并在合并时累积失真 |
| 面向摘要评估的召回率指标（ROUGE-1/2/L） | ROUGE-1/2 分别比较 unigram 与 bigram 重叠，ROUGE-L 比较最长公共子序列，通常以 precision、recall 或 F1 报告 | 参考式摘要评测；高重叠不等于事实正确、连贯或可读 |
| BERT 语义评分（BERTScore） | 用上下文化 token embedding 为候选与参考中的词做最大相似匹配，再聚合为 precision、recall 和 F1 | 语义近似评测；高相似度可能放过实体、数字与否定错误 |
| BART 条件似然评分（BARTScore） | 用预训练 BART 计算在源文本或参考条件下生成候选文本的对数似然，把生成概率当作质量信号 | 流畅度与一致性研究；分数强依赖底层模型、方向和领域 |
| 搬运距离评分（MoverScore） | 用上下文化表示和最优传输计算把候选 token 分布“移动”到参考 token 分布所需的最小代价 | 语义相似评测；计算较重，依然可能忽略关键事实差异 |
| 事实一致性分类器（FactCC） | 构造实体替换、数字修改和否定翻转等合成错误，训练分类器判断摘要句是否受到原文支持 | 摘要事实性筛查；合成错误分布与真实领域错误可能不同 |
| 基于问答的事实性检查（QA-based Factuality） | 从摘要中的陈述生成问题，用原文作为上下文回答，再比较答案是否与摘要陈述一致 | 实体、数字和关系检查；问题生成器与 QA 模型错误会污染结果 |
| 生成式评估（G-Eval） | 把评价标准、源文、摘要和评分格式交给 LLM，让评审模型按 rubric 产生分数与简短理由 | 连贯性、覆盖和风格等自定义维度；必须与人工标签校准并固定评审版本 |
| 实体/数字一致性（Entity/Number Consistency） | 从原文与摘要抽取人名、组织、日期、数值、单位和极性，检查是否出现替换、遗漏或无来源新增 | 发现 entity swap、number drift 和 polarity flip；规则无法覆盖隐含事实 |
| sumy 摘要库 | 一个提供 TextRank、LexRank、LSA 等传统抽取式摘要算法的 Python 库，输入文档后返回选中的原句 | 快速基线和离线处理；语言 tokenizer 与停用词配置影响质量 |
| `rouge-score` 评测库 | Google 提供的 ROUGE-1、ROUGE-2 和 ROUGE-L Python 实现，可选择 stemming 并返回 precision、recall、F1 | 摘要离线评测；必须固定 tokenization、stemming 与聚合配置 |
| 摘要幻觉（Hallucination） | 摘要包含原文未支持的实体、数字、因果或结论，或把不同主体的事实错误合并；语言流畅并不能排除幻觉 | 抽象式摘要上线门禁；需要来源核对、自动检查和高风险人工复核 |

## 13 问答系统

**核心概念：** 问答系统接收自然语言问题并返回答案、证据或拒答结果。给定文章的抽取式 QA 在原文中定位答案跨度；开放域 QA 还要先从语料库找到证据；生成式 QA 则由模型组织最终回答。生产系统需要分别评测“有没有检索到正确证据”和“回答器有没有正确使用证据”，否则无法知道错误发生在哪一层。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 抽取式问答（Extractive Question Answering，Extractive QA） | 联合编码问题与 passage，为每个 token 预测成为答案起点和终点的概率，再从原文返回得分最高的合法跨度 | 法律引用、审计和限定原文问答；模型仍可能选择错误或误导性跨度 |
| BERT 问答头（BERT QA Head） | 在每个 BERT token 表示上使用两个线性分类头，分别输出该位置作为答案开始和结束的 logits | SQuAD 式阅读理解；必须把子词位置映射回原文字范围 |
| 无答案检测（Unanswerable Detection） | 为“上下文没有答案”设置特殊分数或分类头，并将其与最佳答案跨度分数比较后决定抽取还是拒答 | 降低强行抽取；阈值需在包含无答案问题的验证集校准 |
| 开放域问答（Open-domain Question Answering，Open-domain QA） | 系统只接收问题，不预先给定 passage；必须先从大语料检索证据，再由 reader 抽取或生成答案 | 企业知识库和百科问答；检索召回决定回答器可见信息上限 |
| 闭卷生成式问答（Closed-book Generative QA） | 不在请求时检索外部文档，直接让生成模型依赖训练参数中记忆的知识组织答案 | 常识或低风险问答；不适合近期、稀有、私有和需要引用的事实 |
| 检索增强生成（Retrieval-Augmented Generation，RAG） | 先按问题从外部语料检索相关证据，再把问题与证据共同交给生成模型组织答案，并可附带来源引用 | 私有和可更新知识问答；检索与生成任一阶段都可能出错 |
| 检索器-阅读器拆分（Retriever-Reader Split） | Retriever 负责从全库找到 top-k 证据，Reader 只在这些证据上抽取或生成答案；两部分使用独立指标评测 | 定位错误来自召回不足还是答案生成错误，并允许分别替换组件 |
| 重排序器（Reranker） | 对首轮召回的少量 query-document 候选进行联合编码和精细打分，再选最高分文档交给 reader | 提升最终上下文精度；对全库逐文档运行成本过高 |
| BM25/稠密/混合检索（BM25 / Dense / Hybrid Retrieval） | BM25 匹配词项，dense retrieval 匹配语义向量，hybrid retrieval 融合两套排名以兼顾精确词和改写 | 根据产品代码、实体查询与自然语言语义查询比例选型 |
| 斯坦福问答数据集（Stanford Question Answering Dataset，SQuAD） | 给定英文 Wikipedia passage 和问题，标注答案在 passage 中的字符跨度；SQuAD 2.0 还包含无答案问题 | EM/F1 阅读理解基准；不能代表生产开放域、多跳和领域问答 |
| 多跳问答数据集（HotpotQA） | 问题通常需要联合多个 Wikipedia 文档中的事实才能回答，并提供 supporting facts 作为证据标注 | 多跳检索、推理与可解释 QA；模板和百科分布与企业语料不同 |
| 完全匹配（Exact Match，EM） | 对预测与参考做小写、标点、冠词等规范化后检查字符串是否完全相同，相同记 1，否则记 0 | 短答案基准；合理同义词和不同表述会被判错 |
| Token 级 F1（Token F1） | 把规范化预测和参考视为 token 集合，根据重叠 token 数计算 precision、recall 与 F1 | 抽取式 QA；允许部分匹配，但不检查答案事实与来源 |
| 检索召回率@k（Retrieval Recall@k） | 对每个问题检查至少一个正确证据是否出现在检索结果前 k 个位置，再对全部问题求比例 | 诊断 retriever 性能上限；需要可靠的 gold evidence 标注 |
| 引用准确率（Citation Accuracy） | 将答案中的每个引用与其声称支持的具体陈述对应，检查引用文档是否真实包含足够证据 | 生产 RAG 关键指标；引用相关文档不等于引用支持当前结论 |
| 拒答校准（Refusal Calibration） | 根据检索分数、答案置信度或分类器阈值，决定系统应回答还是明确表示证据不足，并比较不同阈值的错误代价 | 高风险 QA 和开放问题；需分别衡量错误回答与过度拒答 |
| 忠实度/答案相关性（Faithfulness / Answer Relevance） | Faithfulness 检查答案陈述是否受提供上下文支持；answer relevance 检查答案是否真正回应用户问题 | RAG 生成质量评测；自动评分必须与人工样本校准 |
| RAGAS 评测框架 | 将 faithfulness、answer relevance、context precision 和 context recall 等 RAG 指标组织成数据集评测流程 | 离线回归与监控；具体指标实现、评审模型与版本配置必须记录 |
| `roberta-base-squad2` 类抽取模型 | 在 SQuAD 2.0 类数据上微调的 Transformer reader，输入问题与 passage 后返回答案跨度或无答案分数 | 给定文档的低生成风险问答；领域外和长文仍需微调或分块 |
| 问答幻觉（Hallucination） | 回答包含检索证据未支持的事实，或把模型参数记忆当成当前文档事实，即使同时给出了看似相关引用 | RAG 与生成式 QA 风险监控；需逐陈述核对证据并允许拒答 |

## 14 信息检索与搜索

**核心概念：** 信息检索（Information Retrieval，IR）根据查询，从大规模文档集合中找出并排序相关内容。稀疏检索依靠词项匹配，稠密检索依靠向量语义相似度，重排模型再对少量候选做更精细的联合判断。检索的目标是提高相关证据进入 top-k 的概率，它不负责生成答案，但会直接限定后续 RAG 能看到什么。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 倒排索引（Inverted Index） | 输入分词后的文档，为每个词项保存出现它的文档 ID、词频和可选位置；查询时读取对应 posting list，而不必扫描全部文档。 | 大规模关键词搜索的基础；更新策略、分词方式和字段设计会影响结果。 |
| Okapi BM25 | 输入查询与文档的词项统计，用逆文档频率（IDF）突出稀有词，用词频饱和限制重复词收益，并按文档长度归一化，输出相关性分数。 | SKU、错误码、人名、法规条款等精确检索；不能直接理解未共享词项的同义表达。 |
| 稠密检索（Dense Retrieval） | 分别把查询（query）和文档（document）编码为稠密向量，再按余弦相似度或内积返回最近的 top-k 文档。 | 同义改写和概念型检索；精确字符串、罕见编号和新实体可能不如 BM25 稳定。 |
| 双编码器（Bi-encoder） | 用相同或不同的编码器独立计算查询向量和文档向量；文档向量可预先存储，在线只需编码查询并做近邻搜索。 | 大规模首轮召回；因为查询与文档在打分前不做 token 级交互，精度通常低于交叉编码器。 |
| 近似最近邻搜索（Approximate Nearest Neighbor，ANN） | 用分区、图索引或量化减少与全库向量逐一比较的计算量，近似返回最相似的 top-k。 | 百万级以上向量检索；索引参数需要在延迟、内存和召回率之间权衡。 |
| FAISS（Facebook AI Similarity Search） | 提供精确和近似向量检索、聚类、量化及 GPU 加速的本地库，输入向量矩阵后构建索引并返回近邻 ID 与距离。 | 原型、离线或自管检索；持久化、权限和分布式服务通常需要应用层补齐。 |
| 向量数据库（Vector Database） | 在 ANN 索引外提供持久化、元数据过滤、更新、复制和服务接口，输入查询向量与过滤条件后返回候选记录。 | 生产语义检索；小语料可直接用内存矩阵或 FAISS，未必需要独立数据库。 |
| 交叉编码器重排器（Cross-encoder Reranker） | 把查询与每个候选文档拼接后联合编码，让 token 充分交互并输出相关性分数，再重新排序 top-N 候选。 | 精排少量候选；质量高但计算不能在大文档库上逐条执行。 |
| 倒数排名融合（Reciprocal Rank Fusion，RRF） | 对每个榜单中的结果按 `1/(k+rank)` 累加分数，不要求 BM25 分数与向量相似度处于同一尺度。 | 融合稀疏与稠密检索；简单稳健，但不能表达某一路信号必须显著更重要。 |
| 加权分数融合（Weighted Score Fusion） | 先把不同检索器的分数校准或归一化，再按验证集确定的权重求和并排序。 | 某类信号明确占优时；若分数尺度或分布漂移，固定权重会失效。 |
| 混合检索（Hybrid Retrieval） | 并行运行关键词稀疏检索与语义稠密检索，合并、去重后通过 RRF、加权分数或重排器得到最终候选。 | 企业检索与 RAG，尤其适合术语、编号和自然语言问题并存的语料。 |
| 稀疏词汇扩展模型（SPLADE） | Transformer 根据输入生成高维稀疏词权重，既保留倒排索引结构，又能给原文未出现但语义相关的词项赋权。 | 兼顾词项匹配和语义扩展；训练、索引体积和推理成本通常高于 BM25。 |
| 后期交互检索（ColBERT / Late Interaction） | 为查询和文档分别保存 token 级向量，再用最大相似度（MaxSim）聚合每个查询 token 的最佳匹配，输出文档分数。 | 专业语料与细粒度长查询；比单向量更精确，但索引显著更大。 |
| 假设文档嵌入（Hypothetical Document Embeddings，HyDE） | 先让生成模型根据查询写一段假想答案或文档，再用该文本的嵌入向量检索真实文档。 | 查询与文档措辞差异大时；假想内容若偏题，会把召回方向一并带偏。 |
| 查询扩展（Query Expansion） | 输入原查询，补充同义词、缩写、实体别名或相关术语，再用扩展查询检索并合并结果。 | 提高召回率；加入不相关词会造成查询漂移并降低精度。 |
| 父文档检索（Parent-document Retrieval） | 索引和召回细粒度小块以精确定位，命中后返回其所属的较大父块，为下游模型提供完整上下文。 | RAG 中兼顾定位精度与上下文完整性；父块过大会重新引入噪声。 |
| 召回率@k（Recall@k） | 在标注为相关的全部文档中，计算有多少比例进入前 k 个结果；需要查询级相关性标注。 | 衡量首轮召回是否漏证据；不反映相关文档在 top-k 内的具体顺序。 |
| 平均倒数排名（Mean Reciprocal Rank，MRR） | 对每个查询取第一个相关结果排名的倒数，再对查询求平均；排名 1 得 1，排名 10 得 0.1。 | 每个查询主要有一个正确答案时；忽略第一个相关结果之后的其他相关文档。 |
| 归一化折损累积增益（Normalized Discounted Cumulative Gain，nDCG@k） | 按结果位置折损多级相关性增益，再除以理想排序的 DCG，得到 0 到 1 的排序质量。 | 多结果且相关程度分级的搜索；依赖稳定的等级标注。 |
| Elasticsearch / OpenSearch | 基于倒排索引提供字段分析、BM25、过滤、聚合和分布式查询的搜索服务。 | 大规模关键词或混合检索；需要维护 mapping、分片和 analyzer。 |
| pgvector | 为 PostgreSQL 增加向量类型、距离算子及 HNSW/IVFFlat 等索引，使关系过滤与向量查询可在同一数据库完成。 | 已使用 PostgreSQL 且规模适中的系统；极大规模需实测延迟与索引维护成本。 |
| Qdrant / Weaviate / Milvus / Vespa | 提供持久化向量索引、元数据过滤、近邻查询和可选混合检索能力的服务。 | 大规模或需要分布式部署时；选型应依据过滤性能、更新模式和运维条件。 |

## 15 主题建模

**核心概念：** 主题建模是在没有逐文档主题标签的情况下，从语料中发现反复出现的内容结构。LDA 把 topic 定义为词的概率分布，并允许一篇文档同时属于多个 topic；BERTopic 一类方法先把整篇文档编码成语义向量，再按相似性聚类并提取代表词。模型输出的是统计模式或 cluster，不是天然正确、唯一的人工主题名称。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 混合成员模型（Mixed Membership）：潜在狄利克雷分配（Latent Dirichlet Allocation，LDA） | 假设每篇文档按不同比例混合多个隐含主题（topic），每个主题又是词的概率分布；从词计数反推文档-主题与主题-词分布。 | 长文和一文多主题分析；词袋假设忽略词序，主题名称仍需人工解释。 |
| 狄利克雷先验（Dirichlet Priors，`alpha`/`beta`） | `alpha` 控制一篇文档倾向混合多少主题，`beta` 控制一个主题倾向集中在多少词上；较小值通常产生更稀疏分布。 | 调整 LDA 主题混合和关键词集中度；含义受具体实现的参数化方式影响。 |
| 折叠吉布斯采样（Collapsed Gibbs Sampling） | 在积分消去分布参数后，反复按条件概率为每个 token 重采样主题归属，再由采样计数估计主题。 | LDA 推断与原理演示；需检查 burn-in、混合和多随机种子的稳定性。 |
| 变分贝叶斯（Variational Bayes） | 用一族较易优化的分布近似难以直接计算的后验，通过最大化证据下界迭代更新参数。 | 大规模或在线 LDA；速度较快，但近似和局部最优会影响结果。 |
| 非负矩阵分解（Non-negative Matrix Factorization，NMF） | 把非负的文档-词矩阵近似分解为文档-主题矩阵与主题-词矩阵，因权重非负而较易解释。 | TF-IDF 上的快速主题基线；主题数需预先给定，一文仍可有多个主题权重。 |
| BERTopic | 把文档编码为语义嵌入，经 UMAP 降维、HDBSCAN 聚类，再用基于类别的 TF-IDF 提取每簇代表词。 | 短文本与交互式主题探索；结果对嵌入模型、降维和聚类参数敏感。 |
| 句子变换器（Sentence Transformer） | 输入句子或文档，输出可直接用余弦距离比较的固定维度语义向量，常作为 BERTopic 的表示层。 | 语义聚类输入；超过模型长度的文档需分块或汇总，否则会截断信息。 |
| 统一流形逼近与投影（Uniform Manifold Approximation and Projection，UMAP） | 根据高维样本的局部邻接图学习低维坐标，尽量保留近邻结构，供聚类或可视化使用。 | 聚类前压缩嵌入；维数、邻居数、距离度量和随机种子都会改变结果。 |
| 基于层次密度的噪声聚类（Hierarchical Density-Based Spatial Clustering of Applications with Noise，HDBSCAN） | 根据不同密度区域建立簇层次，从稳定区域选簇，并把无法可靠归属的样本标为噪声 `-1`。 | 不预设簇数的主题发现；`-1` 表示未归类，不是一个业务主题。 |
| 基于类别的 TF-IDF（Class-based TF-IDF，c-TF-IDF） | 把同一簇全部文本合并为一篇“类文档”，计算词对该簇相对其他簇的区分权重，输出代表词。 | BERTopic 的主题表示；代表词概括的是簇内统计，不保证形成连贯标签。 |
| Top2Vec | 联合使用文档嵌入、降维和密度聚类发现语义相近文档，再从共享向量空间提取主题词。 | 语义主题发现的替代方案；数据量小或密度结构弱时结果可能不稳定。 |
| FASTopic | 通过神经主题建模学习文档、主题和词的表示，侧重比传统深度主题模型更高效的训练与推断。 | 大语料主题发现；使用前应核对实现成熟度、资源开销和可复现性。 |
| 主题一致性（Topic Coherence，c_v Coherence） | 根据高频主题词在参考语料中的共现和语义一致程度计算分数，用来估计词列表是否容易被解释。 | 辅助选择主题数和模型；高分不等于主题对业务有用，不能替代人工审阅。 |
| 主题多样性（Topic Diversity） | 统计不同主题的前 N 个代表词有多少是唯一词，重复过多通常表示多个主题塌缩成相似内容。 | 比较主题区分度；只看词面多样性也可能奖励无意义的稀有词。 |
| 人工主题审阅（Human Topic Review） | 人工同时查看代表词、代表文档和异常样本，判断簇能否稳定命名、是否重复以及是否可用于决策。 | 主题模型上线前必需；需要明确审阅标准和跨审阅者一致性。 |
| LLM 主题命名（LLM Topic Labeling） | 把代表词和代表文档输入大语言模型，让其生成简短主题名称或摘要，输出只用于解释现有簇。 | 提升可读性；生成标签不能反过来当作聚类真值或质量证明。 |
| Gensim LDA | 提供流式语料训练、主题-词查询和文档主题推断的 LDA 实现。 | 传统主题建模实验与批处理；预处理、词典和超参数必须与推断阶段一致。 |
| scikit-learn LDA/NMF | 与 CountVectorizer、TF-IDF 和流水线接口集成的 LDA/NMF 实现，输出文档主题权重与主题词权重。 | 快速实验和基线比较；不自动完成主题解释与质量验证。 |

## 16 N-gram 语言模型

**核心概念：** 语言模型为 token 序列分配概率，并可据此前文预测下一个 token。N-gram 模型只查看固定长度的最近上下文，用语料计数估计条件概率，因此简单、快速、可解释。它的核心困难是数据稀疏：大量合理词组在训练中从未出现，需要平滑、插值或回退为未见事件分配非零概率。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| N 元语言模型（N-gram Language Model，N-gram LM） | 采用有限阶马尔可夫假设，只根据最近 `n-1` 个 token 的计数估计下一个 token 的条件概率，并将各步概率相乘得到序列概率。 | 自动补全、语音识别（ASR）或机器翻译（MT）重打分基线；无法利用超出窗口的依赖。 |
| 最大似然估计（Maximum Likelihood Estimation，MLE） | 用“某 n-gram 出现次数 / 其前缀上下文出现次数”估计条件概率，使训练语料的似然最大。 | 已见 n-gram 的基础估计；任何未见事件都会得到零概率，因此通常必须配合平滑。 |
| 拉普拉斯/加一平滑（Laplace/Add-one Smoothing） | 给每个可能的下一 token 计数统一加一，再按增加后的总数归一化，使未见事件也获得非零概率。 | 解释平滑原理；在大词表中会把过多概率分给未见事件，实际质量通常较差。 |
| 古德-图灵估计（Good-Turing Estimation） | 根据“恰好出现 r 次的事件有多少种”来修正 r 次事件的有效计数，并把部分概率质量留给零次事件。 | 经典频率估计和平滑组件；低频频数本身也需平滑以避免不稳定。 |
| 插值（Interpolation） | 无论高阶上下文是否出现，都按权重混合 unigram、bigram 到 n-gram 的概率，并保证总概率归一化。 | 数据稀疏时平滑过渡；权重应在留出集上估计，而不是任意指定。 |
| 回退（Backoff） | 优先使用可靠的高阶 n-gram；若不存在或计数不足，则乘回退权重并改用低一阶分布。 | 低延迟语言模型；折扣后的剩余概率和回退权重必须正确归一化。 |
| Katz 回退（Katz Backoff） | 对已见 n-gram 使用 Good-Turing 式折扣，把释放的概率质量通过回退权重分配给未见的低阶事件。 | 经典 n-gram 平滑；通常在较高阶模型中作为历史基线。 |
| 绝对折扣（Absolute Discounting） | 从每个非零 n-gram 计数中减去固定折扣 D，再把释放的概率质量分配给回退分布。 | Kneser-Ney 的核心组件；折扣值可按计数桶估计，未必只有一个常数。 |
| Kneser-Ney 平滑（Kneser-Ney Smoothing） | 在绝对折扣基础上，用词出现过多少种不同上下文来构造低阶分布，而不只看词的总频率。 | 通用高质量 n-gram 基线；实现需处理多阶折扣和归一化。 |
| 延续概率（Continuation Probability） | 低阶概率按一个词出现在多少种不同左上下文之后来估计；能在多种上下文出现的词比只在固定短语中高频的词更通用。 | Kneser-Ney 的关键；避免固定搭配中的高频词扭曲 unigram 分布。 |
| 未知词处理（Unknown-token Handling，`<UNK>`） | 训练前把部分低频词替换为保留 token `<UNK>`，让模型学习其概率；推理时未登录词（OOV）映射到同一 token。 | 让测试集 OOV 获得非零概率；训练与评测必须使用同一词表和替换策略。 |
| 困惑度（Perplexity，PPL） | 对留出序列的平均负对数似然取指数，可理解为模型每一步面对的等效候选不确定度；越低通常越好。 | 同一 tokenizer、词表和测试集下比较语言模型；跨 tokenization 的数值不能直接横比。 |
| 概率采样（Probabilistic Sampling） | 从当前 n-gram 条件分布随机选择下一 token，追加后移动上下文窗口，重复直到终止符或长度上限。 | 简单文本生成与自动补全；有限上下文容易造成局部重复和全局语义漂移。 |
| KenLM | 为 ARPA 格式 n-gram 模型提供高效构建、压缩和概率查询，常使用内存映射与优化索引。 | ASR、MT 重打分和低延迟部署；它实现统计语言模型，不替代神经模型训练。 |
| NLTK 语言模型模块（`nltk.lm`） | 提供 n-gram 计数、词表、常见平滑、概率查询、生成和困惑度计算接口。 | 原理学习与小规模实验；大规模部署更适合专用实现。 |

## 17 聊天机器人与 LLM Agent

**核心概念：** 聊天机器人是通过自然语言与用户交互的系统，可能只返回回复，也可能推进一个业务流程。LLM Agent 则在语言模型外增加状态、工具和控制循环，使模型能提出动作、调用外部能力、读取结果并继续决策。两者不是同义词：一个只生成文本的 LLM 聊天界面不一定是 agent，而可靠的生产机器人也常同时使用规则、检索、生成和工具路径。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| ELIZA 式模式匹配（ELIZA-style Pattern Matching） | 用关键词或正则匹配用户句式，提取少量变量，再填入预写回复模板；输出完全由规则决定。 | 极窄领域和确定性演示；遇到未覆盖表达时无法真正理解或泛化。 |
| 人工智能标记语言（Artificial Intelligence Markup Language，AIML） | 用 XML 风格的 pattern/template 规则描述输入模式、变量与回复模板，由解释器匹配最合适规则。 | 传统规则机器人；可审计，但规则冲突和维护成本会随覆盖面快速增长。 |
| 意图路由（Intent Routing） | 输入用户话语，由分类器预测“退款、预订、查询”等预定义意图，再进入对应对话流程或处理器。 | 客服、预订和身份验证；新意图或模糊请求需要兜底路径。 |
| 槽位填充（Slot Filling） | 从当前及历史话语抽取任务所需参数，并逐轮追问缺失槽位，例如日期、地点和人数，输出完整参数表。 | 订票、表单和交易前信息收集；需区分未提供、否定和用户更正。 |
| 有限状态对话（Finite-state Dialogue） | 把对话阶段表示为状态，按用户意图和已填槽位沿允许的边转移，只有特定状态能触发动作。 | 安全关键与合规流程；流程清晰但难以覆盖开放式对话。 |
| 检索式聊天机器人（Retrieval-based Chatbot） | 将用户问题与批准的 FAQ 或回复库进行匹配，返回最相关的现成答案，通常不逐词生成新内容。 | 需要可控措辞的客服自助；幻觉较少，但能力受回复库覆盖限制。 |
| 神经序列到序列机器人（Neural Seq2Seq Chatbot） | 用编码器读取对话上下文、解码器逐 token 生成回复，直接从对话对学习输入到输出的映射。 | 生成式对话历史基线；容易产生安全但空泛的回复和事实漂移。 |
| 意图分类器/路由器（Intent Classifier/Router） | 根据请求类型、风险、置信度和成本，将输入分配给规则、检索、普通生成或代理（agent）路径。 | 生产混合机器人入口；路由错误会使后续能力再强也处理错路径。 |
| LLM 代理循环（LLM Agent Loop） | 控制器反复向模型提供目标与当前状态，接收下一动作，执行工具并写回真实结果，直到终止条件、错误或步数上限。 | 开放式助理、IDE 和业务自动化；必须由外部运行时控制权限、预算与终止。 |
| 工具调用（Tool Calling / Function Calling） | 模型输出工具名和结构化参数，运行时校验后调用搜索、数据库或业务 API，再把结果作为数据返回模型。 | 需要外部事实或执行动作时；模型提议不等于授权，参数与结果都必须验证。 |
| RAG 事实落地（Retrieval-Augmented Generation Grounding） | 先从可信知识库检索证据，再把查询与证据交给模型生成回答，并可附来源引用。 | FAQ、内部知识与可更新事实；若召回错误，生成仍会被错误证据引导。 |
| 混合路由（Hybrid Routing） | 让规则、检索、生成和工具路径并存，根据输入类型与风险动态选择或组合，而非用单一模型处理所有请求。 | 兼顾确定性、覆盖面和成本；需分别监控每条路径与交接失败。 |
| 结构化确认（Structured Confirmation） | 在执行高风险动作前，以明确字段展示目标、金额、收件人等最终参数，并要求用户显式确认。 | 支付、删除、外发消息和数据修改；确认后仍需服务端鉴权与幂等保护。 |
| 直接提示注入（Direct Prompt Injection） | 用户在输入中加入“忽略先前指令”等内容，试图改变模型的优先规则或诱导越权动作。 | 所有 LLM 应用；不能只靠另一段提示词防御，应隔离权限并校验动作。 |
| 间接提示注入（Indirect Prompt Injection） | 恶意指令藏在网页、文档、邮件或工具返回值中，模型读取这些不可信内容后可能把数据误当作指令。 | RAG 与 agent；外部内容必须标记为数据，敏感动作需策略层拦截。 |
| 计划-验证-执行（Plan-Verify-Execute） | 先生成允许动作的计划，执行前检查工具调用是否与计划、权限和参数约束一致，通过后才真正执行。 | 限制工具结果诱导未计划动作；只能降低风险，不是完备安全证明。 |
| 最小权限（Least Privilege） | 每个工具、凭证和任务只获得完成当前目标必需的最小读写范围与有效时间。 | 降低代理被劫持或误操作后的影响面；权限应由运行时强制，而不是写在提示中。 |
| 白名单校验（Allowlist Validation） | 显式列出可调用工具、参数取值、目标资源和允许的状态转移，拒绝所有未匹配请求。 | 高风险代理运行时；白名单仍需配合鉴权、审计和速率限制。 |
| 步数预算与去重（Step Budget / Deduplication） | 给一次任务设置最大模型轮数、工具次数与成本，并记录调用指纹以阻止无进展的重复动作。 | 防止循环和失控成本；达到上限时应返回可诊断的部分结果或失败状态。 |
| 对话摘要（Conversation Summarization） | 将较早轮次压缩为结构化状态或短摘要，只保留目标、约束、决定和未完成事项，再与最近原文共同输入模型。 | 长对话内存；摘要遗漏或错误会在后续持续传播，因此重要事实宜保留原始来源。 |
| 检索式记忆（Retrieval-based Memory） | 把历史事件或轮次写入可搜索存储，当前请求到来时仅检索语义相关记录放回上下文。 | 长期个性化对话；需要处理用户同意、隐私、过期信息和错误记忆删除。 |

## 18 多语言 NLP

**核心概念：** 多语言 NLP 用一个系统处理多种语言，并希望知识能在语言之间迁移。模型通常共享 tokenizer 和网络参数，使不同语言的相似表达进入部分对齐的表示空间，但训练语料与词表分配往往偏向高资源语言。是否“支持某语言”不能只看模型列表，必须检查分词效率、目标语言标注表现和跨语言一致性。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 多语言模型（Multilingual Model） | 在多种语言语料上训练并共享部分或全部 tokenizer、嵌入和网络参数，输入任一受支持语言后输出任务预测或文本。 | 用一个模型服务多语言；“支持”不代表各语言质量相同，必须逐语言验证。 |
| 共享多语言词表（Shared Multilingual Vocabulary） | 在多语言联合语料上训练一个 tokenizer，让所有语言的 token ID 查找同一套嵌入参数，从词元层开始共享模型容量。 | 跨语言参数共享；高资源语言可能占据过多词表，导致低资源语言被拆得更碎。 |
| 共享多语言表示（Shared Multilingual Representation） | 训练目标促使不同语言的等义表达在隐藏空间中靠近，使同一任务头可读取多语言输入。 | 跨语言检索、分类和迁移；对齐不是天然完美，文字系统和语料差异会造成偏移。 |
| 跨语言迁移（Cross-lingual Transfer） | 在有标注的源语言上训练共享多语言模型或任务头，再直接或经少量适配用于目标语言。 | 目标语言缺少标注时；迁移效果取决于语言相似性、预训练覆盖和任务一致性。 |
| 零样本迁移（Zero-shot Transfer） | 训练阶段完全不使用目标语言任务标签，只依靠多语言预训练形成的对齐，在目标语言上直接推理。 | 快速建立低资源语言基线；总体平均分不能替代每种语言的单独评测。 |
| 少样本目标语言微调（Few-shot Target Tuning） | 在跨语言模型上加入少量目标语言标注继续训练，用真实目标分布修正词法、标签和领域偏差。 | 提升长尾语言质量的高性价比手段；小数据需交叉验证并防止过拟合。 |
| 多语言 BERT（Multilingual BERT，mBERT） | 在多语言 Wikipedia 上以掩码语言建模训练的共享 Transformer 编码器，输出 token 或句级上下文表示。 | 多语言分类、NER 等编码任务基线；训练数据和词表对语言覆盖不均。 |
| 跨语言 RoBERTa（Cross-lingual RoBERTa，XLM-R） | 在大规模 CommonCrawl 多语言语料上训练的 RoBERTa 式编码器，使用共享 SentencePiece 词表。 | 多语言分类、NER 和 NLI 常用起点；模型较大，部署成本需评估。 |
| XLM-V | 扩大共享词表以改善多语言分词覆盖的编码器模型，目标是降低部分语言过度切分带来的表示损失。 | 低资源语言 token 任务；是否优于 XLM-R 要按目标语言和任务实测。 |
| 多语言文本到文本迁移变换器（Multilingual Text-to-Text Transfer Transformer，mT5） | 将分类、问答、摘要等任务统一表示为文本输入到文本输出，在多语言 C4 语料上预训练编码器-解码器。 | 多语言生成、摘要与 QA；输出自由度高，结构化任务需要解码与校验。 |
| 不让任何语言掉队（No Language Left Behind，NLLB） | 针对大量语言对训练的神经机器翻译编码器-解码器，输入源语言文本与目标语言标识后生成译文。 | 大规模机器翻译；其专长是翻译，不应直接当作通用分类模型。 |
| BLOOM | 在多语言与代码语料上训练的开放权重、仅解码器（decoder-only）大语言模型，按自回归方式生成后续 token。 | 多语言生成研究；各语言的数据量、能力和安全表现不均衡。 |
| Aya | 面向多语言指令跟随训练的一组模型与数据资源，输入自然语言指令后生成目标语言回答。 | 多语言对话和生成；具体版本的基础模型、语言覆盖和许可证各不相同。 |
| 跨语言自然语言推断（Cross-lingual Natural Language Inference，XNLI） | 将 NLI 样本扩展到多种语言，输入前提与假设，标签为蕴含、中立或矛盾。 | 零样本跨语言推断评测；翻译式数据不完全等同真实本地语言分布。 |
| 多语言句子嵌入（Multilingual Sentence Embedding） | 把不同语言的句子编码到共享向量空间，使译文或等义句的向量相近，并可按距离检索。 | 跨语言检索、去重和聚类；需同时测试语义对齐与单语言区分能力。 |
| 语言排序（LANGRANK） | 根据目标语言与候选源语言的数据规模、地理或类型特征学习迁移效果排序，输出更值得用于训练的源语言。 | 多源语言选择；排序只是先验，应与英文和随机选择基线实测比较。 |
| 语言类型相似性/WALS 特征（Typological Similarity / WALS Features） | 用语序、形态、音系等语言类型数据库特征计算语言间相似程度，作为迁移源选择信号。 | 缩小源语言候选；特征缺失且任务相关性有限，不能代替目标任务验证。 |
| 逐语言评测（Per-language Evaluation） | 对每种语言分别计算准确率、F1、延迟和失败类型，而不是只报告按样本加权的汇总分。 | 防止总体指标掩盖低资源语言失败；同时应报告宏平均和样本量。 |
| 跨语言一致性（Cross-lingual Consistency） | 给模型输入语义等价的不同语言版本，比较预测标签、排序或答案是否一致，并定位语言特有错误。 | 发现语言偏差和表示未对齐；参考翻译本身也需质量控制。 |
| 分词繁殖率（Tokenization Fertility） | 计算一个原始词或字符单位平均被拆成多少模型 token；值越高，同样内容占用的上下文与计算通常越多。 | 衡量低资源语言的上下文和成本税；跨语言比较需使用一致的词边界定义。 |
| Unicode 规范化（Unicode Normalization） | 按 NFC、NFKC 等规则统一组合字符与兼容变体，使视觉或语义等价文本形成稳定码点序列。 | 减少等价文本被切成不同 token；NFKC 可能合并有意义的字符差异，需按领域选择。 |
| 字节回退（Byte Fallback） | 当词表没有覆盖某个字符时，把它编码为原始 UTF-8 字节 token，保证任意文本都可表示而不产生 `[UNK]`。 | 处理罕见文字和异常字符；可靠但会显著拉长序列。 |

## 19 子词分词

**核心概念：** 子词分词在完整单词和单个字符之间选择模型词元：高频词或片段保留为一个 token，罕见词拆成多个可复用片段。这样既限制词表大小，又比纯词级方案更能处理新词和形态变化。Tokenizer 决定 token ID、上下文占用和 embedding 查表位置，因此它是模型参数契约的一部分，不能在微调或部署时随意更换。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 字符级字节对编码（Character-level Byte Pair Encoding，Character BPE） | 先把词拆为字符符号，统计相邻符号对，反复合并频率最高者，输出有序合并规则（merge list）与子词词表。 | 从零训练 tokenizer；初始字符表未覆盖的码点仍需未知词或回退机制。 |
| 字节级字节对编码（Byte-level Byte Pair Encoding，Byte-level BPE） | 从 256 种字节符号开始，在 UTF-8 字节序列上学习高频相邻合并，因此任何输入都能编码。 | GPT-2 类 tokenizer 与开放文本；无 `[UNK]`，但非拉丁语言可能使用更多 token。 |
| 词片（WordPiece） | 从初始符号词表迭代加入能改善训练语料分词目标的子词，编码时通常以最长匹配组合单词。 | BERT、DistilBERT、ELECTRA 系 checkpoint；必须使用与模型训练时完全相同的词表。 |
| 一元语言模型分词器（Unigram Language Model Tokenizer） | 从较大的候选子词集出发，为每个子词学习概率，反复删除对语料似然损害最小的候选；编码可取最佳或采样切分。 | T5、ALBERT 等 SentencePiece 模型；训练机制与 BPE 的逐步合并不同。 |
| 子词正则化（Subword Regularization） | 训练时不固定唯一分词，而从若干高概率切分中随机采样，让模型看到同一文本的多种 token 序列。 | 数据增强与分词鲁棒性；推理通常改用确定性最佳切分。 |
| SentencePiece BPE | SentencePiece 直接从原始 Unicode 文本训练 BPE，把空格编码为普通边界符号并输出模型文件。 | 多语言和无显式空格语言；规范化设置也是模型契约的一部分。 |
| SentencePiece Unigram | SentencePiece 实现的一元语言模型分词，支持 Viterbi 最佳切分和按概率采样多个切分。 | 多语言、小词表与子词正则化；不能与同词表大小的 BPE 假定等价。 |
| Hugging Face Tokenizers | Rust 驱动的 tokenizer 库，可组合 normalization、pre-tokenization、BPE/WordPiece/Unigram 模型和后处理，并提供快速批量编码。 | 自建与部署 tokenizer；保存时需连同全部处理配置，不能只保存 vocabulary。 |
| tiktoken | 针对既有 OpenAI 编码格式优化的高速 BPE 编码与 token 计数库，输入文本后返回 token ID。 | API 成本估算与兼容推理；常用公共接口主要加载既有 encoding，不是通用训练框架。 |
| 合并列表（Merge List） | BPE 训练得到的有序符号对合并规则；编码器按优先级应用它们，决定最终子词边界和 ID。 | tokenizer 复现与模型兼容；只改顺序也会改变全部下游输入。 |
| 词表大小（Vocabulary Size） | 可用 token 的总数，决定嵌入/输出层参数规模，并与平均序列长度形成折中：词表大通常切得更短。 | 从零训练时按模型、语言和领域实测；不存在适合所有模型的固定阈值。 |
| 字符覆盖率（Character Coverage） | SentencePiece 训练时直接保留高频字符所覆盖的语料比例，未覆盖部分交给未知词或字节回退。 | 非拉丁与长尾字符语料；过低损失文字，过高会挤占子词词表。 |
| 特殊 token（Special Tokens） | 为序列开始（BOS）、结束（EOS）、填充（PAD）、未知词（UNK）及角色边界保留的固定 token 与 ID。 | 训练、padding 和聊天模板；新增或重排 ID 会使已有模型读取错误。 |
| 词首空格/空白标记（`add_prefix_space` / Whitespace Marker） | 将空格或词首边界显式纳入编码，使句首单词与句中带前导空格的单词遵循训练时相同规则。 | GPT-2 风格 BPE 和预分词输入；设置必须与 checkpoint 配套。 |
| 分词器哈希锁定（Tokenizer Hash Pinning） | 对 `tokenizer.json`、词表、合并规则和规范化配置计算哈希，并在 CI 或部署清单中校验。 | 防止资产被静默替换导致 token ID 漂移和模型失效。 |
| 往返测试（Round-trip Test） | 对代表文本检查 `decode(encode(text))` 是否等于原文或明确规定的规范化结果，并覆盖空格、Unicode 与特殊 token。 | tokenizer 发布前的正确性回归；往返成功不代表分词效率或模型质量高。 |
| 每词 token 数/压缩率（Tokens-per-word / Compression Ratio） | 统计目标语料被编码后的 token 数相对词数、字符数或字节数的比例，量化序列膨胀。 | 多语言、代码和领域词表选型；比较时必须固定语料和分母定义。 |
| 分词器家族校正（Tokenizer-family Correction） | GPT-2 使用 byte-level BPE，BERT 使用 WordPiece，T5 常用 SentencePiece Unigram；Llama、Gemma 等不同版本的方案可能变化。 | 判断 checkpoint 兼容性；应读取实际 tokenizer 资产，不能按模型家族名猜测。 |

## 20 结构化输出与约束解码

**核心概念：** 结构化输出要求模型返回符合 JSON Schema、正则或语法规则的数据，而不是任意自然语言。提示加校验依靠模型自觉遵守格式；约束解码则在每个生成步骤屏蔽会让当前输出违反语法的 token。它能显著提高格式和类型合法率，但不能判断字段值是否真实、业务动作是否有权限或多个字段在语义上是否一致。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 提示、解析与校验（Prompt + Parse + Validate） | 在提示中描述目标格式，生成后将文本解析为对象，再按字段类型、业务 schema 和取值范围校验；失败进入有限重试或降级。 | 简单低风险任务；必须处理解析失败，不能假定提示一定被遵守。 |
| 原生结构化输出（Native Structured Outputs） | 把 schema 交给模型服务，由服务在生成阶段限制或保证输出结构，并返回可解析对象。 | 托管模型的抽取与工具参数；具体支持的 schema 子集因服务而异，语法有效不等于值真实。 |
| JSON 模式（JSON Mode） | 将解码限制为合法 JSON 文本，确保括号、引号等语法可解析，但通常不强制具体字段、类型或枚举。 | 旧接口兼容和弱格式约束；仍需独立 schema 与业务校验。 |
| 约束解码（Constrained Decoding） | 根据已生成前缀和目标语言状态计算下一步允许的 token 集，在采样或取最大值前屏蔽所有非法候选。 | 高格式合规率的抽取和工具参数生成；复杂 schema 会增加编译或逐步判断开销。 |
| Logit 屏蔽/处理器（Logit Masking / Logit Processor） | 在每个解码步骤读取模型对全词表的 logits，把会违反正则、JSON Schema 或 grammar 的 token 设为负无穷，再重新采样。 | 约束解码底层机制；token 可能包含多个字符，不能简单按单字符规则屏蔽。 |
| 正则约束（Regex Constraint） | 把允许的字符串集合写成正则并编译为自动机，生成时只允许仍可能完成匹配的 token。 | 电话、ID 和固定格式字段；普通正则不适合任意深度的递归结构。 |
| JSON Schema | 声明对象属性、类型、必填字段、数组、枚举和部分组合约束，作为生成与验证共同契约。 | API 参数、实体抽取和配置生成；运行库可能只支持标准的一个子集。 |
| 有限状态机（Finite-state Machine，FSM） | 用有限个状态表示当前合法前缀，读入 token 后转移状态；若无合法转移就屏蔽该 token。 | 正则和有限语言的快速下一 token 约束；不能单独记住无限嵌套深度。 |
| 上下文无关文法（Context-free Grammar，CFG） | 用非终结符和产生式定义可递归嵌套的语言，解析器跟踪当前可接受的终结符并约束生成。 | 抽象语法树（AST）、递归 JSON 和代码结构；文法正确仍不保证程序语义正确。 |
| Outlines | 将 Python 类型、正则或 schema 编译为可用于本地模型的约束生成逻辑，并与后端采样器集成。 | 批量抽取和本地推理；支持范围与行为需以所用版本和 backend 为准。 |
| XGrammar | 把上下文无关文法或 JSON Schema 编译为高效 token mask，面向推理引擎批处理和缓存。 | 递归 schema 与高吞吐服务器集成；仍需业务语义校验。 |
| llguidance | 在 token 级解析 grammar、正则和模板状态，为每一步生成合法 token 集并指导解码。 | 复杂约束输出；需核对目标模型 tokenizer 与运行时集成支持。 |
| vLLM 引导式解码（vLLM Guided Decoding） | 在 vLLM 推理服务内接收 JSON、正则或 grammar 约束，并在批量生成过程中应用相应 logits mask。 | 自托管高吞吐结构化生成；后端和版本会影响可用约束类型。 |
| LM Format Enforcer | 将字符级 JSON Schema 或正则解析状态与 tokenizer 的 token 前缀组合，限制每步合法 continuation。 | 多种本地推理框架的格式约束；格式合法后仍须校验字段意义。 |
| Instructor | 用 Pydantic 模型描述预期结果，封装提示、响应解析、验证错误和重试，并适配多家 LLM 接口。 | Python 结构化抽取；它主要是应用层封装，不等同纯 logit-level 约束。 |
| Pydantic | 用 Python 类型注解定义数据模型，输入解析结果后执行类型转换、字段校验和序列化，并返回明确错误。 | LLM 输出验证、工具参数和服务契约；自定义业务约束仍需验证器表达。 |
| 可空/未知字段（Nullable / Unknown Fields） | 在 schema 中显式允许 `null`、`unknown` 状态或缺失原因，让模型在证据不足时合法表达“不知道”。 | 降低模型为满足必填格式而编造值的压力；下游必须区分未知与空字符串。 |
| 候选检索加约束选择（Candidate Retrieval + Constrained Choice） | 先从巨大候选集合召回少量可能项，再把输出枚举限制为这些 ID，让模型只完成局部判别。 | 超大枚举和实体链接；召回阶段漏掉正确项后，约束选择无法补救。 |
| 重试/回退策略（Retry/Fallback Policy） | 对解析或验证错误分类后进行有限次数修复提示、换模型、返回 `null` 或转人工，并记录原始输出。 | 所有生产结构化生成路径；无限重试会放大延迟、成本和重复错误。 |
| Schema 字段顺序（Schema Field Order） | 按依赖关系安排生成字段：先输出证据、候选或基础值，再输出依赖它们的标签和决策，降低自回归顺序冲突。 | 有显式字段依赖的 schema；可要求简短证据，不应索取或存储私有思维链。 |
| 语义校验（Semantic Validation） | 在结构解析成功后检查跨字段关系、业务规则、数据库约束和来源证据，例如结束时间必须晚于开始时间。 | 任何高风险输出；约束解码只保证形状，不能保证事实、权限或逻辑一致。 |

## 21 自然语言推断（NLI）

**核心概念：** 自然语言推断（Natural Language Inference，NLI）接收前提 premise 和假设 hypothesis，判断前提支持假设、与其矛盾，还是信息不足。这里的“推断”近似普通读者根据自然语言会得出的结论，不是严格的形式逻辑证明。NLI 可复用于零样本分类和 RAG 支持性检查，但模型会受措辞、领域、长度和训练数据捷径影响。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 自然语言推断/识别文本蕴含（Natural Language Inference / Recognizing Textual Entailment，NLI / RTE） | 输入前提（premise）与假设（hypothesis），输出蕴含、矛盾或中立三类概率；RTE 常见为二分类或早期任务名称。 | 支持性判断、矛盾检测和零样本分类；标签是模型判断，不是逻辑证明。 |
| 蕴含（Entailment） | 在普通语言理解下，若前提为真，假设也应为真；例如“她买了两本书”蕴含“她买了书”。 | 事实支持筛查；常识或隐含推理的允许范围必须由数据标注规范定义。 |
| 矛盾（Contradiction） | 前提与假设在同一解释下不能同时为真，例如“会议在周一”与“会议不在周一”。 | 冲突检测和一致性检查；不同时间、主体或条件可能只是表面冲突。 |
| 中立（Neutral） | 前提既不足以支持也不足以否定假设，例如知道“他住在上海”无法判断“他出生在上海”。 | 表达信息不足；不能把中立简单等同于“假设错误”。 |
| Transformer 交叉编码器 NLI（Transformer Cross-encoder NLI） | 将前提和假设组成一个输入序列，经过 Transformer 联合编码，再由分类头输出三类 logits 或概率。 | 句对推断；长文会被截断或稀释，需要分块、证据定位或文档级模型。 |
| 基于 NLI 的零样本分类（NLI-based Zero-shot Classification） | 将每个候选标签改写成假设，如“这段文本属于体育”，分别与原文做 NLI，再按蕴含分数选择标签。 | 没有任务标注时的分类起点；标签措辞、单标签/多标签归一化和阈值都需校准。 |
| 声明拆分加 NLI（Claim Decomposition + NLI） | 先把答案拆成可独立验证的原子声明，再逐条将检索证据作为前提做蕴含判断，最后聚合支持率。 | RAG 事实性评测；声明拆分遗漏或证据跨块会使分数失真。 |
| 斯坦福自然语言推断语料库（Stanford Natural Language Inference，SNLI） | 由图像描述改写出蕴含、矛盾和中立句对的英文数据集，提供大规模三分类训练样本。 | 通用训练基线；体裁较窄且存在假设文本中的标注捷径。 |
| 多体裁自然语言推断（Multi-Genre Natural Language Inference，MultiNLI） | 收集小说、电话、政府、旅行等多体裁英文前提，并标注对应三类假设关系。 | 跨体裁训练和域内/域外验证；仍不代表专业领域或长文推断。 |
| 对抗式自然语言推断（Adversarial NLI，ANLI） | 让人类针对当前模型编写能使其出错的 NLI 样本，分轮迭代收集更困难的推断例。 | 鲁棒性训练和评测；对抗难例分布与真实业务分布可能不同。 |
| 启发式分析系统（Heuristic Analysis for NLI Systems，HANS） | 用控制句法模板构造挑战集，测试模型是否把词汇重叠、子序列或成分包含误当作蕴含。 | 暴露快捷学习（shortcut learning）；覆盖特定启发式，不是完整 NLI 能力测试。 |
| 文档级 NLI 数据集（DocNLI / ConTRoL） | 提供较长前提、跨句证据或组合推断样本，要求模型整合文档信息后判断假设。 | 长前提与多步推断；具体标签构造和长度分布需按数据集分别核对。 |
| 跨语言 NLI（Cross-lingual NLI，XNLI） | 将 MultiNLI 的开发和测试样本人工翻译到多种语言，用统一三分类标签评估跨语言迁移。 | 多语言零样本评测；翻译文本不完全等同各语言自然产生的业务文本。 |
| 医学/科学 NLI（MedNLI / SciNLI） | 使用临床记录或科学文本构造领域句对，保留蕴含、矛盾和中立关系。 | 专业领域支持性判断；模型和阈值不能从通用 NLI 无验证迁移。 |
| 仅假设基线（Hypothesis-only Baseline） | 训练分类器时完全不读取前提，只根据假设文本预测标签；若仍得高分，说明数据存在词面标签线索。 | 检查标签泄漏和表面捷径；这是数据诊断，不是可部署推断方法。 |
| 模板敏感性测试（Template Sensitivity Test） | 为同一类别编写多种等义假设模板，比较零样本分类结果的波动、平均值和最差值。 | 上线前的必要消融；可发现模型其实依赖标签措辞而非输入语义。 |
| 阈值校准（Threshold Calibration） | 在独立标注集上选择蕴含、矛盾或拒答阈值，使精确率、召回率或业务成本达到目标。 | 把连续分数转成决策；不能随意固定为 0.5，分布变化后需重校准。 |
| NLI 能力边界（NLI Limitation Correction） | NLI 输出的是受训练域、长度、措辞和数据偏差影响的模型分数，不能证明声明在现实中为真。 | 幻觉检测只能把 NLI 与可靠证据、规则及人工评测组合，不能宣称单独“解决幻觉”。 |

## 22 文本嵌入模型（Embedding Models）

**核心概念：** 文本嵌入模型把词、句子或文档映射成可计算相似度的数值向量，使语义相近的文本在向量空间中更接近。Dense embedding 用一个短稠密向量概括整段文本，sparse embedding 保留词表维度，multi-vector 则保留多个 token 级向量。Embedding 表示的是为训练目标学到的相似性，不等于事实等价，也不能脱离具体检索数据只看公共榜单选型。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 稠密嵌入（Dense Embedding） | 编码器把整段文本压缩成一个固定维度、绝大多数维度非零的向量，用余弦或内积近似语义相关性。 | 语义检索、聚类与去重；单向量可能丢失长文中的局部细节。 |
| 学习式稀疏嵌入（Sparse Learned Embedding） | Transformer 为整个词表预测权重，并用正则化让大多数维度为零，输出可由倒排索引存储的扩展词项表示。 | 同时重视精确术语与语义扩展；需要稀疏索引并控制索引膨胀。 |
| 稀疏词汇扩展模型（SPLADE） | 通过掩码语言模型 logits 生成文档和查询的稀疏词权重，使原文未出现但相关的词也可参与匹配。 | 专业术语和关键词增强检索；推理、训练与索引成本高于普通 BM25。 |
| 多向量嵌入（Multi-vector Embedding） | 不把全文压成单一向量，而为多个 token、句子或片段保留向量，查询时做局部匹配再聚合分数。 | 长文细粒度检索；存储、内存和查询计算显著增加。 |
| ColBERT 最大相似度（ColBERT MaxSim） | 对每个查询 token 找到最相似的文档 token，取最大相似度后对查询 token 求和，形成后期交互分数。 | 细粒度检索与重排；需要专用多向量索引和压缩策略。 |
| BGE-M3 | 一个支持多语言、长文本以及 dense、sparse、multi-vector 三种检索表示的模型，输出可用于不同索引路径。 | 混合检索原型；三种模式的索引和评分不同，仍应分别及组合评测。 |
| 套娃表示学习（Matryoshka Representation Learning，MRL） | 训练时同时约束向量多个前缀维度完成任务，使前 64、128、256 维等截断版本仍保留较好语义。 | 按存储预算选择维度；只有明确按 MRL 训练的模型才能安全截断。 |
| 维度截断（Dimension Truncation） | 只保留嵌入前 N 个维度再索引与计算相似度，以减少存储、内存和带宽。 | MRL 模型压缩；普通嵌入直接截断可能严重损失召回，必须在领域集验证。 |
| 8 位整数量化（Int8 Quantization） | 为向量选择尺度和零点，将浮点分量近似为 8 位整数，搜索时用量化值或反量化近似距离。 | 大规模索引压缩和加速；需重新测 Recall@k、nDCG 与边界排序误差。 |
| 余弦相似度（Cosine Similarity） | 用两个向量的点积除以各自 L2 范数，衡量方向夹角而弱化绝对长度；范围通常为 -1 到 1。 | 稠密嵌入检索基线；若模型要求内积或已归一化，必须遵循模型卡。 |
| 非对称编码（Asymmetric Encoding） | 查询和文档使用不同指令、前缀或编码路径，让模型学习短问题与长证据承担不同角色。 | 检索模型；把 query/document 模板混用会导致嵌入分布错位。 |
| 查询指令/前缀（Query Instruction / Prefix） | 在查询前加入模型训练时使用的任务说明，如 `query:` 或检索指令，再对完整字符串编码。 | E5、BGE 等模型的正确用法；具体文本和文档端要求应按 checkpoint 核对。 |
| 大规模文本嵌入基准（Massive Text Embedding Benchmark，MTEB） | 汇集检索、分类、聚类、相似度和重排等任务，以统一协议比较嵌入模型。 | 初筛模型与发现能力侧重；公开榜单不能替代目标语言和领域数据。 |
| 信息检索零样本评测基准（Benchmarking IR，BEIR） | 汇集多个领域的查询、文档和相关性标注，测试检索器在未针对目标域训练时的泛化。 | 检查域外检索鲁棒性；数据规模和查询类型与生产系统可能不同。 |
| 归一化折损累积增益@10（nDCG@10） | 对前 10 个结果的多级相关性按位置折损求和，再除以理想排序分数，得到 0 到 1 的质量。 | 嵌入与重排领域评测；需要可靠相关等级，不能单独说明召回覆盖。 |
| BGE / E5 / Nomic / Qwen 嵌入模型 | 多个开放权重文本嵌入模型族，版本在语言、上下文长度、维度、指令格式和许可证上各不相同。 | 本地、隐私和多语言检索；必须按具体 checkpoint 模型卡与领域集选型。 |
| 托管嵌入 API（Hosted Embedding APIs） | 通过远程接口发送文本，由供应商模型返回嵌入向量，无需自行部署推理服务。 | 快速集成和弹性扩缩；需管理数据合规、调用成本、速率限制与版本漂移。 |
| 上下文截断审计（Context Truncation Audit） | 用超过模型窗口、关键信息置于末尾等样本检查 tokenizer 或 API 是否静默截断，并记录实际输入 token 数。 | 长文嵌入前必做；发现截断后应分块、汇总或换长上下文编码器。 |

## 23 RAG 分块策略

**核心概念：** RAG 分块是把原始文档切成可独立编码、索引和召回的单元。块太小会丢失答案所需上下文，块太大又会让 embedding 混入多个主题并占满生成上下文；边界、标题和父子关系通常比固定数字更重要。分块策略必须与查询类型、答案跨度、embedding 窗口和检索指标一起评测，而不是孤立调一个 chunk size。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 固定大小分块（Fixed-size Chunking） | 按固定字符数或 token 数从头到尾切文档，并可在相邻块之间复制一段重叠内容；输出长度较均匀的块。 | 最简单基线；可能切断句子、表格、代码和答案跨度。 |
| 递归分块（Recursive Chunking） | 先尝试按章节或段落分隔符切分，块仍过长时依次改用换行、句号、空格等更细边界。 | 通用文档起点；仍需按真实 tokenizer 检查最终 token 上限。 |
| 句子分块（Sentence Chunking） | 先做句子边界检测，再把一个或若干连续句组成块，可使用滑动句窗保留邻接上下文。 | 普通叙述文本；成本低于语义分块，但句子边界错误会传播。 |
| 语义分块（Semantic Chunking） | 编码相邻句子并计算相似度，在相似度显著下降的主题转折处切开，再用最小和最大长度约束修正。 | 主题切换明显的文档；阈值、嵌入模型和短块合并规则必须调参。 |
| 父子分块（Parent-child Chunking） | 用较小子块（child chunk）建立向量并精确召回，命中后映射回包含它的较大父章节（parent section）供生成。 | 事实型检索同时保留完整上下文；父块过大仍会增加噪声。 |
| 后期分块（Late Chunking） | 先让长上下文编码器对整篇文档产生带全局语境的 token 表示，再按预定边界池化为多个块向量。 | 跨块指代和全局语境重要的长文；依赖可处理整文的 embedder，计算和显存更高。 |
| 上下文化检索（Contextual Retrieval） | 为每个局部块生成或提取简短的文档标题、章节和位置说明，将前缀与原块共同嵌入或建立稀疏索引。 | 合同、手册中脱离章节会歧义的片段；预处理和索引成本增加，生成前缀需防错误。 |
| 分块重叠（Chunk Overlap） | 在相邻块中重复一定数量 token，使跨边界的句子或答案同时出现在至少一个可检索块。 | 边界信息确实丢失时；重叠过大会造成索引膨胀、重复召回和上下文浪费。 |
| 最小/最大块保护（Min/Max Chunk Guard） | 在语义或递归切分后合并过短块、继续拆分过长块，确保每块落入可编码和可理解的长度区间。 | 防止极短碎片或超长块破坏检索；阈值应按语料与模型确定。 |
| 文档边界保护（Document Boundary Guard） | 在拼接、批处理和滑窗时禁止一个块跨越两个源文档，并保留每块唯一来源。 | 保持元数据、权限与来源追踪正确；多文档上下文应在检索后组合。 |
| 元数据感知分块（Metadata-aware Chunking） | 切分时保留标题层级、页码、表格名、说话人、时间和访问权限，并与块 ID 一起写入索引。 | 引用、过滤和对话检索；元数据应来自解析器而不是由模型随意猜测。 |
| 对话轮次分块（Turn-level Chunking） | 以用户-系统轮次为基本单位，或将若干相邻轮组成块，同时保存说话人和时间顺序。 | 客服记录与聊天历史；过细会丢上下文，过粗会混入多个意图。 |
| LangChain 递归字符切分器（RecursiveCharacterTextSplitter） | 按配置的分隔符优先级递归切文本，并使用 `chunk_size` 与 `chunk_overlap` 控制字符或自定义长度函数。 | 快速原型；默认字符长度不等同模型 token 数，应接入目标 tokenizer。 |
| 分层检索评测（Stratified Retrieval Evaluation） | 按事实型、分析型、多跳、表格等查询类型分组计算 Recall@k、nDCG 和失败样本，而不只看总平均。 | 选择分块策略；防止只为简单问题调优后误判整体有效。 |
| 分块大小校正（Chunk-size Correction） | 不存在跨语料通用的 512 或 1024 token 最优值；最优点由答案跨度、查询分布、文档结构和编码窗口共同决定。 | 应在目标数据上做大小、重叠和边界策略消融，而不是套用固定经验值。 |
| 上下文断崖（Context Cliff） | 当块或拼接上下文超过模型有效处理范围后，检索或回答质量可能在某个长度附近突然下降，而非平滑退化。 | 设计分块和上下文预算；需用长度扫描找实际拐点，不能只看标称窗口。 |

## 24 共指消解

**核心概念：** 共指消解（Coreference Resolution）找出文本中哪些 mention 指向同一个实体，例如把“Tim Cook”“这位 CEO”和“他”聚到同一 cluster。系统需要先发现 mention，再为每个 mention 选择 antecedent 或新建实体簇。它处理的是文本内部的指代关系，不等于把实体链接到现实知识库；bridging 等隐式关系甚至不属于严格的同一实体共指。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 指称项检测（Mention Detection） | 从文本中枚举可能指向实体的专名、名词短语、代词和同位语跨度，并为每个跨度计算“是否为 mention”的分数。 | 共指消解第一步；漏检的实体无法在后续恢复，决定召回上限。 |
| 共指聚类（Coreference Clustering） | 根据语义、句法、性数一致性和距离，把指向同一实体的多个指称项连接并传递闭包，输出实体簇。 | 信息抽取、长文理解与对话状态；过度合并会把不同实体污染为一个簇。 |
| Hobbs 算法（Hobbs Algorithm） | 从代词所在名词短语沿句法树向上和向左按固定遍历顺序搜索候选先行词，并用一致性规则过滤。 | 英文代词解析的规则基线；依赖正确句法树，对语义和跨篇章信息利用有限。 |
| 指称项对分类器（Mention-pair Classifier） | 为任意两个指称项提取文本、距离和一致性特征，输出它们是否共指的概率。 | 经典系统；独立两两判断可能违反传递性，转成全局簇时需额外聚类策略。 |
| 指称项排序（Mention Ranking） | 对当前指称项的所有先行词候选及“新实体”选项联合打分，选择最高者作为链接决策。 | 比独立 pair 分类更贴近真实决策；候选剪枝漏掉正确先行词后无法恢复。 |
| 端到端跨度共指（End-to-end Span Coreference） | 枚举并剪枝可能的文本跨度，联合学习指称项分数与先行词分数，最终把链接结果合并成簇。 | 现代神经 coreference 主架构；长文的跨度组合和显存成本高。 |
| SpanBERT 式编码器（SpanBERT-style Encoder） | 通过掩码连续跨度及边界目标预训练，让跨度边界表示更好地概括内部实体内容，再供共指打分使用。 | 英文实体跨度与共指模型；跨语言和专业领域需重新验证。 |
| LLM 提示式共指（LLM-prompted Coreference） | 在提示中要求模型列出指称项跨度、先行词或实体簇，并用 JSON 等 schema 返回映射。 | 短文快速基线；可能改写原文或漏跨度，长文还需窗口合并与证据校验。 |
| 滑动窗口合并（Sliding-window Merge） | 对重叠窗口分别做共指，利用共同指称项、实体名和兼容约束对齐窗口内簇，输出文档级簇。 | 超过模型上下文的文档；错误簇一旦跨窗口合并会继续传播。 |
| 回指（Anaphora） | 后出现的指称项指向前文实体，例如“张敏到场。她发了言”中的“她”。 | 常规代词和名词短语解析；先行词通常在前但可能跨句较远。 |
| 下指/前指（Cataphora） | 先出现的代词或描述指向后文才明确出现的实体，例如“在他发言前，李明先看了稿子”。 | 规则系统的困难情况；只向前搜索先行词会漏掉。 |
| 桥接回指（Bridging Anaphora） | 两个表达不是同一实体，但通过部分-整体、集合-成员等关系可推知联系，如“买了汽车，车轮有划痕”。 | 篇章理解与关系抽取；它不是严格同一实体共指，不应放进同一 cluster。 |
| 零回指（Zero Anaphora） | 句子省略可由上下文恢复的主语或宾语，系统需要先发现空位再确定其指向。 | 中文、日文等省略常见语言；仅面向英文显式代词的模型通常不适用。 |
| MUC 指标 | 将实体簇看成需要连接的 mention 链，计算预测需添加或删除多少链接才能得到 gold 聚类。 | 共指评测；偏好大簇，对单例（singleton）和 mention 检测错误不够敏感。 |
| B³ 指标 | 对每个 mention 比较其预测簇与 gold 簇的交集，计算 mention 级 precision/recall 后平均。 | 直观反映每个 mention 的簇纯度与完整性；单例和 mention 集不一致时实现细节重要。 |
| 基于实体对齐的共指评测（CEAF-φ4） | 在预测簇与 gold 簇之间寻找一对一最优对齐，再按对齐相似度计算 precision、recall 和 F1。 | 惩罚把多个实体过度合并；不同 CEAF 相似函数不能混用。 |
| BLANC / 链接感知实体评测（Link-based Entity-Aware，LEA） | BLANC 同时评价共指与非共指链接，LEA 按实体重要性加权其正确链接比例。 | 补充 CoNLL F1 的盲点；应与标准三指标一起报告。 |
| CoNLL F1 | 计算 MUC、B³ 与 CEAF-φ4 三个 F1 的算术平均，作为英文共指任务常用汇总分。 | 模型比较；仍应报告 mention 检测、过合并、漏合并和各单项分数。 |
| AllenNLP / spaCy 共指组件（Coreference Components） | 提供预训练神经共指模型、管线接口或实验实现，输入文档后输出 mention 簇。 | 英文原型；使用前需确认组件是否仍维护、模型版本和语言兼容性。 |

## 25 实体链接与消歧

**核心概念：** 实体链接（Entity Linking，EL）把文本中的 mention 映射到知识库中的唯一实体 ID，例如区分“Jordan”指篮球运动员、国家还是另一位同名人物。典型流程先生成候选实体，再利用上下文、先验或模型进行消歧，并允许输出 NIL 表示知识库中没有匹配项。NER 负责找 mention，EL 才负责确定它在现实知识库中是谁。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 实体链接（Entity Linking，EL；Entity linking (EL)） | 为文本中的指称项（mention）生成知识库候选，结合上下文选择唯一实体 ID；若知识库无对应项则输出 NIL。 | 知识图谱、搜索与实体分析；它解决“现实中是谁”，不同于 NER 只判断文本跨度和类型。 |
| 别名索引（Alias Index） | 建立表面形式（surface form）到候选实体 ID、名称和先验频率的映射，例如“苹果”可指公司或水果概念。 | 高速候选生成；别名覆盖和语言规范化直接决定候选召回上限。 |
| Wikipedia 重定向与消歧页（Wikipedia Redirects / Disambiguation Pages） | 从重定向标题、锚文本和消歧页提取实体别名及同名候选，构造开放域候选表。 | 百科实体链接；dump 必须版本化，并清理列表页、过期实体和循环重定向。 |
| 候选生成（Candidate Generation） | 根据别名、字符串相似度、流行度或向量检索，从整个知识库快速缩小到少量 top-k 实体。 | 大知识库 EL 第一阶段；正确实体未进入候选后，精排模型无法补救。 |
| 流行度先验（Popularity Prior） | 从历史锚文本或链接统计估计 `P(entity \| mention)`，同一名称优先选择过去最常链接的实体。 | 低延迟消歧基线；会压制新实体、长尾实体和特定领域含义。 |
| 上下文相似度（Context Similarity） | 将 mention 周围句子与候选实体的名称、描述或属性编码并比较，选择语义最匹配的候选。 | 同名实体消歧；上下文太短或实体描述过时都会降低效果。 |
| BLINK 式双编码器（BLINK-style Bi-encoder） | 分别编码 mention 上下文和全部实体描述，预计算实体向量后用 ANN 召回 top-k 候选。 | 大型知识库的向量化 EL；速度快，但两端缺少细粒度联合交互。 |
| 交叉编码器消歧（Cross-encoder Disambiguation） | 将 mention 上下文与每个候选实体描述拼接后联合编码，输出匹配分数并重排候选。 | 对少量候选精排；计算昂贵，不能直接对全知识库逐实体比较。 |
| REL / ESS | 实体链接或实体消歧的系统与方法名称，通常组合 mention 检测、候选生成、局部打分和全局一致性。 | 通用英文 EL 基线；部署前应核对论文定义、训练语料、代码维护状态和 KB 版本。 |
| 基于检索的实体生成（Generative Entity Retrieval，GENRE） | 将实体链接转为自回归生成规范实体名称，模型读取上下文后逐 token 生成目标实体。 | 生成式 EL；必须将解码限制在知识库实体集合，避免不存在的名称。 |
| Trie 约束解码（Trie-constrained Decoding） | 把所有合法实体名或 ID 建成前缀树，生成时只允许沿当前前缀仍存在的 token 分支继续。 | 防止输出知识库外实体；保证“存在”但不保证语义上选对。 |
| 多语言 GENRE（mGENRE） | 用多语言输入生成统一知识库中的规范实体名称，使不同语言 mention 可链接到同一实体 ID。 | 跨语言实体链接；别名、文字系统和低资源语言能力需逐语种评测。 |
| ELQ / ExtEnD | 联合完成指称项检测与实体链接的端到端模型，从原文直接输出 mention 跨度及知识库实体。 | 减少流水线组件；检测与链接错误纠缠，定位问题比两阶段系统更困难。 |
| NIL 检测（NIL Detection） | 在所有候选都不可信或知识库不存在目标实体时，明确输出 NIL，而不是强行链接到最相近的已知实体。 | 新实体、内部实体和 KB 过期场景；阈值需要独立 NIL 样本校准。 |
| AIDA-CoNLL | 基于新闻文本、使用 Wikipedia/YAGO 实体标注的英文实体链接基准，包含同名 mention 的上下文消歧。 | 通用英文模型比较；新闻分布与企业、医学等领域差距较大。 |
| 指称项召回率@k（Mention Recall@k） | 统计有 gold 实体的 mention 中，正确实体进入候选 top-k 的比例，单独衡量候选生成阶段。 | 诊断 EL 召回上限；不反映候选内部最终排序。 |
| Top-1 准确率/NIL F1（Top-1 Accuracy / NIL F1） | Top-1 准确率检查最终首选实体是否正确；NIL F1 同时衡量未知实体判断的 precision 与 recall。 | 生产 EL 评测；还应按实体流行度、语言和 mention 类型分层。 |
| Wikidata / Wikipedia / DBpedia | 提供实体 ID、名称、别名、描述和关系的开放知识库，可作为候选来源和最终链接目标。 | 开放域 EL；必须固定 dump/version，避免训练、索引和评测实体集合漂移。 |
| 领域知识库（Domain Knowledge Base，Domain KB） | 企业、医学或法律内部维护的实体表与关系库，通常有自定义 ID、别名、状态和权限。 | 专业实体链接；需要自建 alias、NIL 样本、版本迁移和人工标注集。 |
| NER → 共指 → EL（NER → Coreference → Entity Linking） | 先识别 mention 跨度与类型，再把同一文档内的指代合并，最后利用汇总上下文链接到实体 ID。 | 文档级实体规范化；任何阶段的漏检或误合并都会级联到后续。 |

## 26 关系抽取与知识图谱

**核心概念：** 关系抽取（Relation Extraction，RE）从文本中识别实体之间的语义联系，例如从“居里夫人出生于华沙”得到“居里夫人—出生地—华沙”。关系通常表示为主语、关系、宾语组成的三元组。知识图谱（Knowledge Graph，KG）把规范化实体作为节点、关系作为边，还应保存证据来源、有效时间和限定条件。抽取出一句关系短语并不等于得到可用图谱事实；实体链接、本体映射、证据验证和去重都是必要步骤。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 主语-关系-宾语三元组（Subject-Relation-Object Triple） | 用主体实体、规范化关系类型和客体实体表示一条最小事实，例如 `(居里夫人, 出生地, 华沙)`；还可附加时间、来源和置信度 | 知识图谱构建、结构化分析和 Graph RAG |
| 模式/正则关系抽取（Pattern/Regex Extraction） | 编写可匹配固定句式的正则或语言模式，并把命中的文本槽位映射为主体、关系和宾语；规则没有覆盖的表达不会被抽取 | 高精度、句式稳定的合同、日志和模板文本；覆盖率有限 |
| 赫斯特模式（Hearst Patterns） | 一组从自然语言枚举结构中发现上下位关系的模式；例如从“编程语言，如 Python 和 Rust”得到 `Python is-a 编程语言` | 构建分类体系、发现 is-a/上下位关系；只覆盖特定句法形式 |
| 监督式关系分类（Supervised Relation Classification） | 输入一句话和其中标出的两个实体，从预先定义的关系标签集合中预测它们的关系，通常还包含 `no_relation` 表示没有目标关系 | 有标注数据、关系类型固定的医学、金融和企业知识抽取 |
| TACRED / ACE / KBP 数据集 | 包含文本、实体位置和人工关系标签的关系抽取数据集或评测系列；不同数据集的实体类型、关系集合和负例定义不同 | 训练和比较监督式关系抽取模型；不能跨数据集直接比较分数 |
| 远程监督（Distant Supervision） | 将已有知识图谱中的实体对与同时提到这两个实体的句子自动对齐，把图谱关系当作弱标签，从而减少人工标注 | 大规模生成关系训练数据；句子未必真正表达图谱关系，因此标签噪声高 |
| 开放信息抽取（Open Information Extraction，Open IE） | 不预先规定关系类型，直接从句子中抽取文本形式的关系短语和论元；例如得到 `(Alice, works at, Acme)`，其中 `works at` 仍是原文短语 | 探索未知关系、快速构建候选事实；同义关系写法不统一，必须规范化后才能稳定查询 |
| 闭合本体关系抽取（Closed Ontology Relation Extraction） | 先定义允许出现的有限关系字典或本体，例如 `{出生地, 任职于, 收购}`；模型输入实体对及上下文，只能输出其中一个关系或 `无关系` | 需要固定字段、可验证输出的生产知识图谱与合规抽取；发现不了字典外的新关系 |
| 生成式 LLM 关系抽取（Generative LLM Extraction） | 把文本和关系 schema 交给大语言模型，让它生成结构化三元组；模型可处理灵活表达，但可能生成原文没有的实体或关系 | 新领域快速原型和少样本抽取；必须校验 schema、实体 ID 和原文证据 |
| 文本跨度锚定（Span Anchoring） | 为三元组中的每个实体和关系保存其在原文中的起止字符位置，使抽取结果能精确回到支持它的文字 | 审计、证据高亮和生成式抽取防幻觉；隐含关系可能没有直接关系短语 |
| 来源追踪（Provenance） | 为每条事实保存文档 ID、原文跨度、文档版本、抽取器版本和时间等来源信息，回答“这条事实从哪里来” | 事实追溯、删除、更正、冲突处理和人工复核 |
| 验证步骤（Verification Pass） | 将生成的实体、关系和三元组逐项与原文跨度、允许的关系 schema 及实体库比对，不满足约束的结果被拒绝或送审 | 降低 LLM 生成无依据事实的比例；不能自动证明复杂隐含推理正确 |
| 覆盖检查（Coverage Pass） | 检查已经发现的实体与关系线索是否都被某个三元组解释，对遗漏候选再进行一次抽取或人工检查 | 提高关系召回率；补抽范围过宽会增加误报 |
| 锚定-抽取-验证-补充流程（Anchor-Extract-Verify-Supplement） | 先定位原文实体和关系线索，再生成三元组，随后验证证据并检查遗漏；这是可采用的分阶段工程流程，不依赖 AEVS 这一缩写 | 需要可审计证据的 LLM 关系抽取；额外步骤会增加延迟和调用成本 |
| 实体规范化（Entity Canonicalization） | 将不同表面写法和别名映射到同一个实体 ID，例如把 `Apple Inc.`、`Apple` 和 `苹果公司` 合并为同一节点 | 防止知识图谱出现重复实体；需要实体链接和稳定知识库 |
| 关系规范化（Relation Canonicalization） | 将 `works at`、`任职于`、`is employed by` 等不同关系短语映射到统一关系 ID，例如 `任职于` | 让开放抽取结果能够去重、统计和查询；映射错误会合并本来不同的关系 |
| 时间限定符（Temporal Qualifiers） | 在关系上记录开始时间、结束时间或有效时间点，使同一实体对在不同时期可以具有不同关系状态 | 任职、婚姻、地址、价格和职位等会随时间变化的事实 |
| REBEL 关系抽取模型 | 将关系抽取建模为“输入文本，生成带特殊标记的三元组序列”，并在百科实体关系数据上预训练 | Wikipedia/Wikidata 风格关系抽取起点；专业领域和自定义关系需要再训练 |
| 邻接表图结构（Adjacency-List Graph） | 为每个主体节点保存一组“关系类型和相邻客体节点”，从而以列表形式表示知识图谱的出边 | 小型知识图谱存储、遍历和教学；复杂查询通常使用图数据库或索引 |
| 知识图谱构建流水线（KG Construction Pipeline） | 依次执行实体识别、共指消解、实体链接、关系抽取、本体映射、证据验证和图加载；任一上游错误都会传播到最终图谱 | 从非结构化文档构建可查询、可追溯的生产知识图谱 |

## 27 LLM 与 RAG 评测

**核心概念：** LLM 评测把开放式输出拆成可观察的质量维度，例如正确性、相关性、事实支持、检索覆盖、工具调用和安全性。固定算法指标便宜且可重复，LLM-as-judge 能评复杂自然语言准则，但会产生位置偏差、长度偏好和版本漂移。可靠评测需要版本化数据集、人工校准、分层指标和失败样本审查，而不是只看一个平均分。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 确定性指标（Deterministic Metric） | 按固定公式比较预测、参考答案或证据集合；在输入、预处理和配置相同时应返回完全相同的分数。 | 回归测试和低成本批量评测；可重复但往往难覆盖开放答案的等义表达。 |
| LLM 评审（LLM-as-a-Judge） | 将任务输入、候选输出、可选参考答案和评分量规（rubric）交给评审模型，返回类别、分数及简短依据。 | 正确性、风格等开放维度；必须与人工标签校准并监控模型版本漂移。 |
| RAGAS | 面向 RAG 的评测框架，组合查询、回答、检索上下文和参考信息，计算忠实度、相关性与上下文指标。 | 离线实验和数据集评测；不同版本的指标定义、是否需要参考答案及 judge 模型需固定。 |
| DeepEval | 将 LLM 指标封装成测试用例、断言和数据集运行，可接入测试代码与 CI，并支持自定义评审准则。 | 回归门禁和批量比较；框架自动化不能替代指标有效性校准。 |
| 生成式评测（Generative Evaluation，G-Eval） | 把自然语言评分准则和评审步骤交给 LLM，让其按离散等级或概率评估候选文本。 | 连贯性、正确性、风格和领域规则；对 prompt、评审模型与输出长度敏感。 |
| 忠实度（Faithfulness） | 把回答拆成声明，判断每条声明是否能由提供的上下文推出，再聚合为支持比例。 | 生成事实落地性；声明拆分和蕴含判断本身也会出错，且不检查上下文是否真实。 |
| 答案相关性（Answer Relevance） | 衡量回答是否直接回应原查询的意图与所需信息，而不是仅与查询主题相似。 | 检测冗余、跑题和答非所问；需区分简洁拒答与无关回答。 |
| 上下文精确率（Context Precision） | 检查检索到的块中有用证据是否排在前面，可按每个相关位置的 precision 聚合。 | 评估重排器和分块噪声；需要相关性标签或可靠 judge。 |
| 上下文召回率（Context Recall） | 将参考答案所需事实或 gold 证据与检索块比较，估计必需信息被召回的比例。 | 衡量 retriever 覆盖；通常依赖参考答案或证据标注，生成正确不代表召回完整。 |
| 基于 NLI 的评审器（NLI-based Judge） | 把检索上下文作为前提、回答声明作为假设，用蕴含分数判断声明是否受支持。 | 低成本事实性信号；受领域、长文本截断和复合声明影响。 |
| 嵌入相关性（Embedding Relevance） | 分别编码查询与回答或检索块，用余弦相似度估计语义接近程度。 | 大规模低成本筛查；高相似度不等于事实正确，也可能奖励复述问题。 |
| 评分量规设计（Rubric Design） | 明确每个分数等级的必要条件、排除条件、边界案例和正反示例，使评审输出可复核。 | 降低 judge 随意性；量规应针对单一维度，避免把正确性和风格混成一分。 |
| 人工校准集（Human Calibration Set） | 由多位审阅者对代表性样本给出标签和理由，解决分歧后作为自动评审的锚点。 | 检查 judge 是否符合业务判断；应覆盖常见、边缘和高风险失败。 |
| 斯皮尔曼等级相关系数（Spearman Rank Correlation） | 将自动分数与人工分数转为排名，计算两者单调关系，值越高表示排序越一致。 | 校准连续或有序评分；阈值应由风险和置信区间决定，不能固定迷信 0.7。 |
| 成对顺序随机化（Pairwise Order Randomization） | 对 A/B 候选交换展示顺序并重复评审，若胜负随位置变化则标记不稳定或聚合两次结果。 | 降低位置偏差；会增加一倍左右评审调用成本。 |
| 跨模型评审（Cross-model Judging） | 让不同于生成模型的模型评审，或由多个异构评审器投票/分工，减少模型偏爱自身风格。 | 减轻自我偏好；共享训练数据与共同盲点仍可能造成一致的错误。 |
| 数据集版本化（Dataset Versioning） | 固定样本 ID、内容、分层、参考答案和变更记录，任何修改产生新版本并保留历史结果。 | 保证不同模型与时间的分数可比；不可静默修题后沿用旧基线。 |
| 底部分位审查（Bottom-quantile Review） | 除均值外，抽查最低 1%、5% 或失败样本，按错误类型统计严重程度和重复模式。 | 发现被平均数掩盖的灾难性错误；分位阈值应配合业务风险。 |
| CI 回归门禁（CI Regression Gate） | 在模型、prompt 或检索配置变更时自动运行固定评测，若绝对指标低于门槛或相对基线退化则阻断发布。 | 保护生产质量；需控制 judge 随机性，并允许有审计记录的人工豁免。 |
| LangSmith / Phoenix | 记录 LLM 调用轨迹、检索内容、工具步骤、数据集和人工标注，支持过滤线上样本与比较实验。 | 人工复核和可观测性；工具本身不定义什么是业务正确。 |
| Promptfoo | 用配置批量运行 prompt、模型和测试断言，比较输出并支持安全与红队用例。 | 回归、模型对比和配置化评测；复杂语义断言仍需可靠 judge 或人工标签。 |

## 28 长上下文评测

**核心概念：** 长上下文评测检查模型在输入变长后能否定位、整合并推理分散信息。模型接口允许输入某个 token 数，只说明“可接收”，不说明在这个长度上仍能稳定利用所有内容。评测应区分简单事实检索、多事实聚合和多跳推理，并同时报告信息深度、上下文长度、准确率、延迟和成本。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 大海捞针测试（Needle-in-a-Haystack，NIAH） | 在大量无关填充文本的指定位置插入一条唯一可验证事实，再提问并检查模型能否原样或等义恢复。 | 长上下文最小健全性测试；主要测定位，不能代表复杂推理。 |
| 深度×长度网格（Depth × Length Grid） | 同时改变关键信息位于上下文的百分比深度和总 token 长度，在二维网格上记录准确率。 | 发现中部退化和实际容量；单一“放在末尾”的测试会漏掉位置偏差。 |
| 多针测试（Multi-needle Test） | 在不同位置插入多条事实，问题要求分别找出或联合汇总，观察事实数量增加后的遗漏与混淆。 | 测注意力竞争和多事实聚合；评分要区分部分找回与全部正确。 |
| RULER | 通过可扩展合成任务测试变量追踪、检索、多跳、聚合等长上下文能力，并可生成不同长度输入。 | 比单一 NIAH 更全面的模型比较；合成任务仍需配合真实领域评测。 |
| LongBench v2 | 汇集长文问答、对话、代码、结构化数据和复杂推理任务，使用较长真实或构造输入评估模型。 | 接近真实长上下文任务的横向比较；具体版本、语言和评分协议必须固定。 |
| 多轮共指检索（Multi-Round Coreference Resolution，MRCR） | 在长多轮上下文中放入相似或重复信息，要求根据当前指代找到正确轮次中的目标内容。 | 长对话的重复信息辨别与指代；比单条唯一 needle 更容易暴露混淆。 |
| 无字面匹配测试（No Literal Matching，NoLiMa） | 设计查询与目标信息没有直接词汇重叠的样本，必须依靠语义或世界知识建立联系后定位 needle。 | 区分语义检索与关键词扫描；对所需外部知识的假设需明确。 |
| HELMET | 将多篇文档拼接成长输入，通过信息检索、排序或生成任务检查模型能否选择性使用相关文档。 | 多文档长上下文；应同时分析文档数量、位置和干扰相似度。 |
| BABILong | 把 bAbI 的符号化事实和推理问题嵌入大量无关文本，随着长度增长检查推理链是否保持。 | “干草堆中的推理”（reasoning-in-a-haystack）；合成逻辑不等同开放域理解。 |
| 中间遗失（Lost in the Middle） | 模型通常更善于利用上下文开头和结尾的信息，而对中间位置证据的准确率下降。 | 深度分层测试和 prompt 布局；不能用把所有重要内容放两端替代系统性检索。 |
| 有效上下文（Effective Context） | 在目标任务、准确率阈值、模型配置和提示模板下，模型仍能可靠利用的实际上下文范围，而非接口最大窗口。 | 生产容量规划；必须分别测检索、聚合与推理，不能只报一个标称 token 数。 |
| 有效检索长度（Effective Retrieval Length） | 在固定 needle 分布和通过率阈值下，模型仍能定位所需事实的最大输入长度。 | 比标称窗口更有业务意义；阈值和任务难度不同会得到不同长度。 |
| 有效推理长度（Effective Reasoning Length） | 在多跳或聚合任务达到目标准确率时可用的最大长度，通常小于简单检索的有效长度。 | 长文分析选型；应与有效检索长度分开报告。 |
| 退化曲线（Degradation Curve） | 固定任务和位置分布，逐步增加上下文长度，绘制准确率、延迟和成本随长度变化的曲线。 | 模型升级、缓存、分块和 RAG 决策；曲线比单个最大窗口数字更可靠。 |
| 首 token 延迟（Time to First Token，TTFT） | 从请求发出到收到第一个输出 token 的时间，长输入主要增加模型预填充（prefill）阶段开销。 | 评估长 prompt 的交互延迟；还应同时报告总生成时间与吞吐。 |
| 单查询成本（Cost per Query） | 汇总输入 token、输出 token、检索、重排和评审调用的费用或算力消耗。 | 比较长上下文直塞与 RAG 架构；需同时约束质量，不能只选最便宜方案。 |
| 固定回归工具链（Fixed Regression Harness） | 固定样本、随机种子、长度生成方式、needle 深度、提示和评分规则，并保存模型/API 版本。 | 每次模型或 API 升级时复测；供应商静默更新会破坏历史可比性。 |
| 标称窗口校正（Advertised-window Correction） | 模型能在接口层接收 N token 只说明不会拒绝输入，不代表能在 N token 上稳定定位或推理。 | 生产选型必须以目标领域任务测得的有效上下文为准。 |

## 29 对话状态跟踪（DST）

**核心概念：** 对话状态跟踪（Dialogue State Tracking，DST）把多轮任务型对话压缩成当前可执行的结构化状态，例如 `restaurant.area=north`、`people=4`。每一轮都要根据用户新增、否定、确认或纠正的信息更新 slot，同时保留未被修改的旧值。DST 是语言理解与业务动作之间的状态层；格式正确并不表示值提取正确，高风险动作仍需要校验和用户确认。

| 技术 | 是什么 | 典型使用场景与边界 |
|---|---|---|
| 对话状态（Dialogue State） | 用结构化的领域-槽位-值（domain-slot-value）集合概括当前用户目标、已知约束、未填字段和必要历史。 | 预订、客服和表单式对话；状态是业务动作输入，不应只存在于自然语言摘要中。 |
| 领域 Schema（Domain Schema） | 定义业务领域、允许的槽位、数据类型、枚举、必填条件和跨字段约束，作为 DST 与后端共同接口。 | 任务型对话契约；变更时需要版本和迁移规则。 |
| 闭合词表槽位（Closed-vocabulary Slot） | 槽位值只能来自预先列出的有限枚举，例如区域为 `{北区, 南区}`，系统输出类别 ID 或标准值。 | 区域、价格档位和舱位；适合分类与约束选择，但无法表示新值。 |
| 开放文本槽位（Free-form Slot） | 槽位值是从话语复制、抽取或生成的任意文本，例如姓名、地址、时间和备注。 | 开放值 DST；必须做格式规范化、实体校验和敏感信息保护。 |
| 槽位-值分类（Slot-value Classification） | 对每个槽位在固定本体（ontology）的候选值及 `none/dontcare` 中分类，输出当前轮状态值。 | 固定 ontology 的传统 DST；候选规模大或新值频繁出现时不适用。 |
| 生成式对话状态跟踪（Generative DST） | 将对话历史和 schema 输入生成模型，让其逐 token 输出槽位值或完整 JSON 状态。 | 开放词表和多领域对话；可能编造未出现的值，需约束与证据校验。 |
| 规则/正则槽位抽取器（Rule/Regex Slot Extractor） | 用关键词、正则、词典和确定性转换从当前话语提取日期、编号、金额等值，再写入指定槽位。 | 窄领域、合规与低延迟基线；自然语言变体超出规则后召回下降。 |
| 增量状态更新（Incremental State Update） | 比较当前轮与已有状态，只对明确新增、修改、否定或清除的槽位生成 patch，其他值原样保留。 | 成本低且易审计；依赖正确的更正、否定和删除策略。 |
| 全状态重生成（Full-state Regeneration） | 每一轮根据 schema 与完整或压缩历史重新输出全部当前槽位，后端用新对象替换旧状态。 | 容易表达槽位依赖；长历史成本高，模型也可能无依据删除旧值。 |
| 更正处理（Correction Handling） | 识别“其实、改成、不是 A 是 B”等信号，撤销受影响的旧值并写入新值，同时保留变更来源轮次。 | DST 必备状态转移；不能把更正后的新旧值同时保留为有效。 |
| 否定处理（Negation Handling） | 区分用户拒绝某候选、清空已有值与设置新的负向约束，例如“不要北区”不是 `area=北区`。 | 约束搜索和预订；状态 schema 需能表达排除值或 `not` 条件。 |
| TripPy | 使用复制机制从当前用户话语、系统话语或历史状态中复制槽位值，并预测值的来源位置。 | 传统 schema-based DST；依赖槽位定义和监督数据，跨领域需适配。 |
| BERT-DST | 用 BERT 编码对话上下文，为各槽位预测状态类别、候选值或文本跨度，输出结构化 belief state。 | 有标注的多领域传统 DST；长历史与开放新值处理能力取决于具体变体。 |
| LLM + LoRA DST | 使用低秩适配（Low-Rank Adaptation，LoRA）微调大语言模型，使其按 schema 从对话生成状态。 | 有 MultiWOZ 风格训练数据的开放值 DST；仍需结构和业务校验。 |
| 无本体 DST（Ontology-free DST） | 不预先列出全部槽位名和值，模型从对话中发现并生成可能的属性-值对，再映射到业务 schema。 | 开放领域探索；生产后端仍需要命名治理、合并和版本控制。 |
| Pydantic/Instructor DST | 用 Pydantic 类型定义状态对象，通过 Instructor 封装生成、解析、校验错误和有限重试。 | 少标注快速原型；结构合法不表示槽位值来自用户或符合业务事实。 |
| 约束解码 DST（Constrained Decoding DST） | 根据 JSON Schema、枚举和 grammar 屏蔽非法下一 token，确保输出可解析且闭合槽位只取允许值。 | 提高格式合法率；不能保证模型正确理解更正、否定或上下文。 |
| 联合目标准确率（Joint Goal Accuracy，JGA） | 只有一轮中全部目标槽位和值都与 gold 状态完全一致才计 1，再对轮次求平均。 | DST 标准严格指标；槽位越多越难全对，应配合逐槽位指标。 |
| 槽位精确率/召回率/F1（Slot Precision/Recall/F1） | 把预测和 gold 状态拆成槽位-值对，计算预测中正确比例、gold 中找回比例及调和平均。 | 定位具体字段失败并补充 JGA；需统一 `none`、`dontcare` 和规范化规则。 |
| 多领域 Wizard-of-Oz（Multi-domain Wizard-of-Oz，MultiWOZ） | 收集餐馆、酒店、出租车等领域的任务型对话，并提供对话行为、belief state 和数据库结果标注。 | DST 训练与基准；2.0、2.1、2.2 等版本修订不同，报告时必须注明。 |
| ASR 规范化（Automatic Speech Recognition Normalization） | 对语音识别文本中的口语数字、时间、专名和同音错误生成标准形式，并保留候选及置信度供 DST 使用。 | 语音机器人；过早只保留一条 ASR 结果会丢失可恢复的不确定性。 |
| Schema 版本化（Schema Versioning） | 为槽位定义、枚举和迁移规则标版本，保存每段对话使用的版本，并提供旧状态到新状态的转换。 | 防止 schema 更新破坏历史会话、训练数据和回放评测。 |
| 确认流程（Confirmation Flow） | 当槽位置信度低或动作风险高时，向用户展示关键参数并请求显式确认，确认结果再写回状态。 | 支付、预订、删除和合规字段；确认不能替代后端鉴权和最终校验。 |

## 常见误解与更准确的说法

| 常见简化说法 | 更准确的解释 |
|---|---|
| “抽取式摘要/QA 不会幻觉” | 它不生成原文之外的新 token，但仍会选错跨度、断章取义或保留误导性指代；应说“生成性幻觉风险较低”。 |
| “BPE 能处理所有 OOV” | 只有字节级方案或覆盖完整字符集并有 fallback 的方案才能保证任意输入可编码；字符级 BPE 仍可能产生未知字符。 |
| “GPT-2 / Llama 都是 byte-level BPE” | GPT-2 是明确的 byte-level BPE；Llama/Gemma 各代 tokenizer 不同，应读取具体 checkpoint 的 tokenizer 资产和模型卡。 |
| “共享多语言词表带来零样本翻译” | 零样本迁移来自共享参数、训练目标、语料覆盖和语言标记等共同作用，共享词表只是其中之一。 |
| “注意力权重就是模型解释” | 它是可视化信号，不是因果解释；至少需要消融、输入扰动或反事实验证。 |
| “NLI 检查即可解决 RAG 幻觉” | NLI 受 claim 切分、领域、长度和校准影响，只能作为一个事实性信号。 |
| “约束解码保证答案正确” | 它主要保证语法/schema 合法；事实、跨字段一致性和业务权限必须另行校验。 |
| “reasoning 字段必须排在 answer 前” | 字段依赖顺序有时会影响生成，但不是普适定律；优先输出可审计 evidence/brief rationale，避免要求或存储私有 chain-of-thought。 |
| “固定 chunk size/overlap 是生产默认” | 块大小和 overlap 必须围绕 query 类型、答案跨度、模型窗口与 retrieval recall 做消融。 |
| “MTEB/排行榜第一就是最佳模型” | 公共榜单只用于候选初筛，最终选择看领域 nDCG/recall、p99 延迟、成本、语言和许可证。 |
| “上下文窗口等于有效上下文” | 可接收长度、有效检索长度和有效推理长度是三个不同概念。 |
| “AEVS 是通用标准框架” | Anchor、Extract、Verify、Supplement 这种分阶段抽取思路有用，但 AEVS 不应在没有明确来源时当作行业通用标准名称。 |

## 组合流水线速查

| 目标 | 建议顺序 |
|---|---|
| 文档知识图谱 | 预处理 → NER → coreference → entity linking → relation extraction → ontology mapping → provenance-aware graph load |
| 企业 RAG | 解析/清洗 → metadata-aware chunking → BM25 + dense → RRF → cross-encoder rerank → grounded generation → citation/faithfulness eval |
| 多语言分类 | Unicode normalization → checkpoint tokenizer → multilingual encoder → target-language few-shot → per-language calibration/eval |
| 高风险结构化抽取 | schema → candidate/span extraction → constrained output → semantic/source validation → confidence threshold → human review |
| 任务型对话 | intent/domain routing → DST update → schema validation → policy/action selection → high-risk confirmation → tool execution → outcome verification |
| LLM 回归评测 | versioned dataset → deterministic metrics → calibrated judge → bottom-quantile review → CI threshold → model/prompt/retrieval change log |
